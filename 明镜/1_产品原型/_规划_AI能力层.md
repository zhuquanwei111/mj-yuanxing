## 〇、一句话总纲

**明镜的 AI = 会看数的分析师（感知）＋会下判断的运营（认知）＋会写东西的助理（生成）＋会跑腿的执行者（执行），四类能力挂在同一层，被「明镜助理」统一调度；AI 只产草稿、卡片和提醒，所有改状态的动作都等人拍板。**

这句话拆开就是车总要的三个答案：

| 车总的问题 | 明镜的回答 |
|---|---|
| 适配 AI 的 Harness 架构，他们怎么让 AI 调用工具？ | 和 Claude Code 完全同构：模型 ↔ 工具循环。Claude Code 的工具箱是 Bash/Read/Write，明镜的工具箱是**数据工具/规划工具/通知工具/任务工具**等 10 个业务域工具（见第二节） |
| 人如何通过某些功能让 AI 去调用某些功能？ | 三条入口：**点按钮**（按钮=预置意图，如「生成规划」直接调规划工具）、**问助理**（自然语言→意图匹配→选工具）、**系统自动触发**（事件驱动：播完自动出复盘、掉数自动出预警——E1-E10 事件流） |
| 哪些是 AI 做的？哪些是人做的？ | 全站已有的 🤖/✍️/🖐 三层图例就是答案：🤖 AI 自动跑完人只看结果；✍️ AI 出草稿人改定；🖐 人操作才发生。**唯一铁律：改状态的动作必须人点按钮**（采纳/发送/派人/确认）——这对应 Claude Code 里每个写操作前的人工 approve |

## 一、AI 能力分类（四类 × 每类具体能力项）

> 命名规则：能力名 = 动词短语；每项标「做什么 / 输入 / 输出 / 在哪页呈现」。

### 1. 感知类（AI 的眼睛——把散落数据收拢成 AI 能用的上下文）

| 能力项 | 做什么 | 输入 | 输出 | 在哪页 |
|---|---|---|---|---|
| **主播数据感知** | 读单个主播的近 14 天音浪/时长/峰值/停留/环比，打包成生成类能力的上下文 | 主播档案 + d14 数组 | 上下文包（供规划/复盘/解读） | P22/P23/P24（数据依据卡） |
| **全局大盘感知** | 汇总全公司 86 人：在播数/今日音浪/开播率，按组聚合 | ALL_ASSETS 全量 | 大盘快照（供周报/决策建议） | P13/P93（跨组对比） |
| **异常信号感知** | 规则引擎先筛：流水连续下滑、连续 2 天未播、停民率异常 | 近 14 天序列 | 异常信号（进入认知类写原因） | P13 异常汇总/P15 |
| **事件感知** | 监听业务事件（转单/结业/账单/打卡回传——E1-E10） | 事件流 | 待办卡/系统通知的触发源 | P20/P25/P90 |
| **沟通感知** | 读沟通记录与群消息，供情绪判断与跟进建议 | comms 数组 | 情绪上下文 | P30D/P24 |
| **排期感知** | 读工单与转交单的时间地点分布 | WORKJOBS + handoffs | 排期视图 + 冲突候选 | P50 周历 |
| **外部基准感知** | 行业基准线（开播率/活跃率/留存）与平台公告 | 基准库（演示值） | 对比上下文 | P13 行业基准/P03 |

### 2. 认知类（AI 的大脑——判断、归因、推荐）

| 能力项 | 做什么 | 输入 | 输出 | 在哪页 |
|---|---|---|---|---|
| **流失归因** | 对异常信号写一句人话原因（五类预置：心态情绪/大哥纠纷/收入不及预期/家庭个人/合规问题）+ 建议动作 | 异常信号 + 沟通记录 | 预警卡：谁+什么信号+一句原因+派人按钮 | P15 |
| **撞档检测** | 同主播同天两张未完成单→提醒合并或改期 | 排期感知输出 | 撞档提醒卡（完成自动翻「已消解」） | P50 |
| **档位判断** | 按官方口径算任务完成度→定平台分成档位（12%） | 有效天/时长/流水 | 档位+应付金额 | P13 任务条/P70 |
| **对账差异** | 平台结算单 vs 公会自算逐行比，差异行标黄 | 两边结算数据 | 差异行（有差异=要查，无差异=一致） | P70 对账明细 |
| **结算预审** | 无流水新人按保底预发标黄；分成高于保底的判「保底无」 | 合同+流水 | 标黄行+账单预审注记 | P70/P71 |
| **转化漏斗** | 线索→邀约→试播→签约各环节计数与转化率 | LEADS 状态 | 漏斗图+最强/最弱环节 | P30 漏斗视图 |
| **经营决策建议** | 基于各组环比+新组状态给 1-2 条建议（带数据依据），采纳即转任务 | 大盘快照 | 建议卡+采纳按钮 | P93 决策建议 |
| **基准解读** | 我们 vs 行业：好在哪差在哪一句话 | 基准对比数据 | 解读一行（强项/补强点） | P13 行业基准 |
| **意图理解** | 助理把自然语言匹配到能力/工具（10 角色 × 3-4 意图） | 用户输入 | 意图命中→回复+执行卡 | AI Tab（全角色） |
| **薄弱点定位** | 按考核记录算课目通过率，最低的排前 | EXAMS | 薄弱课目卡 | P42 |

### 3. 生成类（AI 的手——出草稿、出文案、出报表）

| 能力项 | 做什么 | 输入 | 输出 | 在哪页 |
|---|---|---|---|---|
| **直播规划生成** | 三段式：填信息→AI 分析中（可视化逐条）→草稿（时段+时长+画面自检六项+话术+数据目标） | 主播档案+近14天+表单参数 | 结构化草稿（✍️双栏：采纳/修改/不用） | P23 |
| **复盘生成** | 昨晚三句话：哪里好/哪里掉/今晚怎么办+数据快照+AI 依据展开 | 昨晚场次数据 | 复盘草稿（确认后才推主播） | P24 |
| **脚本/选题生成** | 按人设+近期数据出选题建议与脚本要点草稿 | 人设+数据+热点 | 选题卡（P60 入池）+脚本草稿（P61） | P60/P61 |
| **邀约话术生成** | 两稿轮换（夸作品+讲模式+约试播三句式） | 线索资料 | 话术草稿（采纳/换一条/不用） | P31 |
| **差异解释生成** | 账单确认页自动附一句「本月实发比上月多/少约 X 元：音浪涨/跌 X%」 | 两月账单 | 一句话解释 | P71/P84 |
| **经营周报生成** | 本周要点+环比变化+下周关注 | 大盘快照 | 周报样式卡（可导出） | P13 |
| **助理回复生成** | 按角色业务答业务问题（话术/操作/数据），回复里嵌执行卡 | 问题+角色上下文 | 回复+执行卡 | AI Tab |

### 4. 执行类（AI 的腿——调工具、发通知、改状态；**全部带拍板门禁**）

| 能力项 | 做什么 | 拍板门禁 | 在哪页 |
|---|---|---|---|
| **执行卡调度** | 助理回复里嵌执行卡（如「生成规划 · 小雨›」），点开带参直达对应业务页 | 点执行卡=人发起 | AI Tab |
| **通知下发** | 群发通知（选人→发→逐人送达徽章）、平台公告（P03 发→P92 收）、系统卡（结业/预警/账单事件自动进 P90） | 发送前人工填写/确认 | P20/P03/P90 |
| **任务下达** | 决策建议采纳→自动生成组长任务（ST.dirTasks），组长端可见、完成回写 | 采纳按钮 | P93→P94 |
| **状态流转** | 选题四档推进/回退、账单双向确认（发确认→主播确认→翻转+留痕）、签约三步推进 | 每步人工点击 | P60/P71/P32 |
| **回执回写** | 转单完成→发起人待办+1；结业→转单+系统卡+名单移出；预警处理→沟通记录回写 | 处理人点「完成/回执」 | P25/P20/P50 |
| **数据下钻** | 点指标→弹层看构成（活跃名单/按组拆分/口径注记） | 点卡片=人发起 | P13/P20 |
| **月报导出** | 一键出月度报表预览（真机导出 Excel/PDF） | 点导出 | P70/P13 |

> 四类能力的铁律（与账本 AI 两容器规则一致）：**感知与认知类产出的卡片默认只读（🤖 浅底卡，可展开）；生成类一律 ✍️ 双栏（左草稿右拍板）；执行类必须有显式的人点按钮**。AI 永远不静默改业务状态。

### 2.3 一条完整调用链走给你看（以「运营给小雨生成下周规划」为例）

```
运营小林（人）
  → P21 卡片快捷操作「生成规划」（按钮=预置意图）
  → P23 段1 表单（主播已预填=参数已带）
  → 点「开始生成」（人发起）
  → 规划工具 genPlan 被调：
      先调 数据工具 readData（读小雨档案+d14）——感知类
      再跑 认知（环比↑、近7天日均×1.15 定目标）——认知类
      再 生成 结构化草稿——生成类（段2「AI 分析中」逐条可视，就是在演这个过程）
  → 段3 草稿出来（✍️ 双栏）
  → 人拍板：采纳 → 修改 → 发给主播（执行类：状态流转+通知工具）
  → 主播端 P81 可见 + P22 规划史落库（数据同源）
  → 全程 P23 页面上的 ailine 标着「AI 做了什么 / 人拍什么板」
```

这一条链里 AI 与人的边界：**AI 做了读数、算目标、写草稿；人做了填参数、采纳、改定、发送。AI 没有替人发送过任何东西。**

## 三、人机协作流（8 个核心场景的分工表）

> 格式：谁发起 → AI 做什么 → 人拍板什么 → AI 再做什么（收尾）。每条都是原型里真实点得通的链路。

| # | 场景 | 谁发起 | AI 做什么 | 人拍板什么 | AI 再做什么（收尾） | 页 |
|---|---|---|---|---|---|---|
| 1 | **直播规划** | 运营（点生成/助理「生成规划·小雨」） | 三段式：读数据→算目标→写草稿（时段/自检六项/话术/目标） | 采纳 or 修改 or 不用；改定后点「发给主播」 | 状态流转已发送→主播端 P81 可见→P22 规划史落库 | P23/P81/P22 |
| 2 | **盯场复盘** | 系统自动（播完触发） | 汇总昨晚数据→写三句话→附数据快照与 AI 依据 | 运营「确认无误」或「补充修改」→「推给主播」 | 推送→主播端 P82 可见→复盘史落库 | P24/P82 |
| 3 | **流失预警** | 系统自动（数据信号达标） | 规则筛→写一句原因（五类）→建议动作 | 老板「派人」（选处理人） | 待办挂卡到处理人→处理完→沟通记录回写；再达标重新预警（E7） | P15/P20/P30 |
| 4 | **结算核对** | 财务（月度例行动作） | 读平台单+按合同自算→标差异行（活动返点差 ¥500）+预审标黄保底预发 | 财务查差异→走申诉或确认一致→「出月账单表」 | 账单到 P71→主播确认留痕→P71 翻转（E5） | P70/P71/P84 |
| 5 | **妆造排期** | 运营（P22 转交）→妆造接单 | 撞档检测（同主播同天两单→提醒合并）| 阿灿「接单」→「办完回执」 | 状态翻已完成→撞档自动「已消解」→运营 P20 收回执（E1/E2） | P50/P51/P52 |
| 6 | **招人转化** | 经纪人（录线索/要话术） | 生成邀约话术两稿→漏斗计数与转化率 | 采纳话术、标已签约、三步推进 | 漏斗自动更新→交接进培训（E8/E9） | P31/P32/P30 |
| 7 | **结业转段** | 培训师（任务全过后） | 汇总任务完成与考核→结业评估就绪提示 | 「通过结业评估」一键拍板 | 自动转单运营+系统卡进 P90 公会群+带教名单移出+KPI 更新（E3） | P41/P25/P90 |
| 8 | **助理问答** | 人（任何角色，问一句/Tab 问） | 意图匹配→答业务→嵌执行卡 | 人点执行卡（=授权 AI 带参直达） | 带参打开对应业务页（如 P23 已预填小雨）→回到场景 1 的链路 | AI Tab |

> 补一句「谁发起」的规律：**B 端三成是人发起（规划/账单/任务），七成是事件自动发起（复盘/预警/回执）；C 端（主播）几乎全是 AI 主动推（规划/复盘/账单确认提醒），主播只做确认和打卡。** 这就是「主理人经营主播，AI 主理一切流程」的产品叙事。

## 五、Harness / Claude Code / Codex 架构对标（给车总看得懂的版本）

### 5.1 同构对照表

| Claude Code（通用编程） | 明镜（垂直业务） | 一句话类比 |
|---|---|---|
| 用户输入 prompt | 用户点按钮 / 问助理 | 说人话，AI 听 |
| 模型决定调哪个工具 | 意图匹配 → 选能力 → 调工具 | AI 自己选工具 |
| 工具：Bash/Read/Write/Edit/Grep | 工具：数据/规划/复盘/话术/预警/排期/账单/通知/任务/报表（10 个） | Claude 的工具箱是「文件系统」，明镜的工具箱是「业务系统」 |
| 工具调用前人工 approve（权限模式） | 执行类能力全部带拍板门禁（采纳/发送/派人/确认） | 危险动作都要人点头 |
| 工具调用日志（透明可查） | ailine「AI 做了什么 / 人拍什么板」+ P96 引擎页 | 每一步都有账 |
| Plan Mode（先出计划再动手） | ✍️ 草稿模式（AI 出稿人改定） | 先给方案再执行 |
| 沙箱（Codex：受限执行环境） | 权限三层（公司/范围/字段）+ 多租户隔离 | AI 只能在权限圈里干活 |
| Agent 循环：调工具→看结果→再调→直到完成 | 明镜循环：感知→认知→生成→人拍板→执行→事件驱动下一步 | 都是循环，明镜的循环里**每一圈都有人** |

### 5.2 两个关键差异（也是明镜的设计优势）

1. **工具是垂直的，所以更可控。** Claude Code 的 Bash 几乎什么都能做，所以审批要细；明镜的 10 个工具每个都是窄域业务函数（genPlan 只出规划、genBill 只算账），出错面小、审批点自然清晰——**垂直化是把 Harness 的安全模型做简单的方法**。
2. **明镜多了一个「事件驱动」入口。** Claude Code 全靠人发起对话；明镜七成场景是事件自动发起（播完出复盘、掉数出预警、到期出提醒）——AI 不只被动应答，还主动值守。这是 ToB 产品的本质差异：**Claude Code 是「你问它答」，明镜是「它守着，有事叫你，你拍板」**。

### 5.3 给车总的三句话总结

1. 明镜的 AI 架构就是 Harness 架构的**业务域翻译**：模型不动，把「工具箱」从文件系统换成公会业务的 10 个工具。
2. 人机分工的铁律全站只有一条：**AI 产草稿和卡片，人点按钮才改状态**——这条对应 Claude Code 的人工审批，是整个体系的安全底座。
3. 落地顺序建议：先把 10 个业务工具做成真服务（它们本来就是要写的业务接口），再把助理的意图匹配接上模型——**工具先行，智能后置**，和 Claude Code 的成熟路线一致。
