## 1 · 产品背景（30 秒读懂）

**明镜 = 直播公会的 AI 工作平台。** 一个公会（例：星曜传媒）每天要回答：谁在播、赚多少、谁要跑、今天先干什么。明镜把这件事做成一个手机 APP：AI 替人盯着，人拍板。

- **一套壳、三端**：公会端（10 个员工角色）＋ 主播端（私人助理）＋ 平台运营端。
- **12 种角色**：公会老板 / 运营总监 / 运营组长 / 一线运营 / 经纪人 / 培训师 / 妆造视觉 / 编导 / 剪辑 / 财务 / 平台运营 / 主播。每个角色一套工作台、一套底部 Tab。
- **公会端的日常**：运营早上 7:30 上班先消化昨晚夜场数据，然后盯今天要播的 13 个主播；老板看大盘、处理风险；经纪人招人；培训师带新人；妆造排期跑现场；财务月底对账。
- **主播端**：今天几点播、昨晚播得怎么样、话术问题随时问、这个月能拿多少。

### 1.1 产品最独特的语义（必答题）

全站只有一条铁律：**AI 产草稿和卡片，人点按钮才改状态。**

| 图例 | 含义 | 视觉上必须做到 |
|---|---|---|
| 🤖 | AI 自动跑完，人只看结果 | 一眼看出"这是机器给的结论" |
| ✍️ | AI 出草稿，人改定 | 一眼看出"这还没生效，等我拍板" |
| 🖐 | 人操作才发生 | 一眼看出"这里是我干的" |

**同一屏里这三种必须不用读小字就能分清**——这是明镜区别于"又一个 AI 聊天框"的地方。

### 1.2 同类标杆：拆 2–3 个真实产品（拆法有要求）

不要写"参考飞书"这种形容词。要写下**某个具体界面用什么视觉通道表达了什么信息**：

- 用**长度**表达"掉了多少"（两根条一长一短），而不是写"下滑 16%"；
- 用**明度**表达"风险档"（同一张图里越深越严重），而不是写"高风险"；
- 用**位置**表达"先做哪个"（排在上面的就是优先级），而不是写"建议优先处理"；
- 用**时间轴上的区间**表达"连续三天"，而不是写"连续 3 天"。

**拆解这些"通道 → 意思"的对应关系，比拆配色和版式有用。**你在拆的时候，记下每个标杆**当家用的是哪两个通道**。

### 1.3 不要参考的东西（这一轮明确排除）

- **项目里已有的旧原型**（纯灰度极简那版，51 屏）：**它的视觉一律不要参考**。内容与字段本文 §3 已给全，其实不必去读它。

- **常见的 AI 默认套路**：深色底＋紫蓝渐变＋玻璃拟态卡、圆角＋柔和投影通吃、emoji 当图标、**所有信息都装进等距格子或表格**、每个数字配一个圆角小色块。如果你发现自己的方向正在变成这些，说明它不是从这个产品推出来的，重来。

明镜——"照见／看清"。用不用这个意象由你的方向决定，也可以完全不用。

### 2.3 十个板块：每一块都要有自己的主张

> ② **至少有两块要大改到"一眼认不出是常规做法"**——不是每块都推倒重来，但也不许只有一块出彩。

### 2.4 「常规 → 大胆」的尺度示范（教你尺度，不是给你答案）

上一轮的产出大多停在左列。大胆是往右列走——**具体做成什么样，必须你自己想；照抄下面的词就等于又交了一份常规卷**：

| 常规做法 | 大胆的手法类型（选一种去实现） |
|---|---|
| 一行文字说明一件事 | **变成一根轴**：位置＝时刻或先后，长度＝量 |
| 一列卡片，按时间排 | **变成一个空间**：排布即优先级，越靠前越急 |
| 一张表／一堆格子 | **变成一张图**：明度＝档位，面积＝体量 |
| 一个入口写一个词 | **让入口承担状态**：它本身显示"今天还有几件" |
| 一段解释＋一个按钮 | **让交互替代解释**：做一次就看懂，不用读 |
| 每块都一样重 | **让节奏不均匀**：该大的大、该静的静，靠留白分层 |

> 10 个板块里，**至少覆盖上面两种手法**，并且**至少有两块让人"咦"一下**。

## 3 · 要表达的信息（**语义清单**：表述可压缩，语义不得增删）

> **这一节不是让你照抄的文案，而是这一页要表达的全部信息。**

> - **数字、状态名、按钮名照抄**（业务事实：13 / 10 / 6 / 18.8万 / 34.2万 / 1.1万 / −42% / −16% / 38秒→26秒 / 41秒 / 86 / 11场 / 2.4% …）。
> - **句子可以压缩、可以拆成字段／标签／数值／图形**，但语义不得增删。
> - 目标：整屏可见正文汉字 **≤ 700**。下面这些信息若逐句照排大约 1300 字——**你必须把其中一半以上变成控件或图形**。

### 3.0 同一句话，至少有五种画法（这一节是本轮的关键）

拿阿哲这张卡里的信息当例子：*"连续 3 天流水下滑，近 7 天比前 7 天少 16%；进场停留从 38 秒掉到 26 秒；18 点档被新起的两个同类场分走人气。"*

| 用哪个通道 | 这句话被画成什么 |
|---|---|
| **字段／标签**（最省事，但一批里别都用它） | `近7天 −16%` ｜ `停留 38秒 → 26秒` ｜ `标签：18点档 同类场 ×2` |
| **长度（条）** | 两根并排的条：前 7 天 vs 近 7 天，短的那根自己就说明了 −16%；停留再画两根（38 / 26） |
| **明度／色阶** | 14 天排成一条色带，越深越高；最近三天连续变浅＝连续下滑，一眼看到"连续 3 天" |
| **斜率／角度** | 一条往下走的折线，末端标 −16%；停留是第二条更陡的线；两条线一起看就是"跌得比流水更狠" |
| **时间／节奏** | 时间轴上把"连续 3 天"画成一段区间，再把"18 点档同类场出现"的时间点对齐在同一根轴上——**冲突关系自己浮出来** |
| **位置／顺序** | 把它排在这一屏靠前的位置（位置就是优先级），不必写"建议优先处理" |

**两张同一句话的对照**（自己体会差别）：

```
通道 A｜字段标签式                     通道 B｜明度色阶 + 长度
┌──────────────────────┐              ┌──────────────────────┐
│ 阿哲                  │              │ 阿哲      ▂▂▃▄▄▃▂▁▁▁▁  ← 14天色带，后三天变浅
│ 流水 −16%             │              │ 前7天 ████████ 18.5万 │
│ 停留 38秒 → 26秒      │              │ 近7天 ██████   ─16%  │
│ 标签 18点档 同类场 ×2 │              │ 停留  ████████ → █████ 38→26
└──────────────────────┘              └──────────────────────┘
```

> **两条原则**：
> ① 能用数字、标签、图形回答的，不要用句子回答。
> ② **能用量（长度／面积／深浅／斜率）回答的，不要只用格子或标签回答。**
>
> **同一个方向里，同类信息要用同一种通道**（不然读者要重新学一遍）；**但不同方向之间，当家通道必须换人**。

## 4 · 必须被设计到的语义（不可省略）

1. **来源四态**：🤖预警 / 🤖自动摘要 / ✍️草稿 / 🖐记录——一眼可分。
2. **草稿＋拍板**：草稿内容与「采纳／修改／不用」的关系，以及"还没生效"的状态感。
3. **风险三档**：有风险／ 待跟进／ 正常——同一体系里分级；**除颜色外必须有第二种区分手段**（形状／位置／图标／字重／密度／明度），只靠颜色不算过。
4. **人机分工行**：每张 AI 卡里都要有「AI 做了什么 ｜ 人拍什么板」的位置——这是产品规矩，不是装饰。
5. **可下钻**：KPI 要让人知道"能点开看构成"。
6. **动作三档**：主／次／弱（含"催一下""不用"这种轻动作），层级要成立。
7. **状态集合**：直播中（带"正在发生"的感觉）／ 已下播 ／ 未开播 ／ 今日未播 ／ 排休 ／ 请假 ／ 新人·待首播。
8. **文字预算**（§0 门槛①）：整屏正文 ≤ 700 字，每卡正文 ≤ 2 行 × ≤ 24 字。

## 7 · 编码通道：每个方向选 1–2 个当家的

**视觉通道不是装饰，是语法。**同一份信息，换个通道就是另一个设计——这是本轮的评分重点。

| 通道 | 它擅长回答 | 用它的样子 |
|---|---|---|
| 1 **位置与顺序** | 谁先做、谁更重要 | 排在最前／最高／最中央；不画框，靠排位 |
| 2 **长度（条）** | 差多少、掉多少、完成多少 | 横条、竖条、进度、量条、对比双条 |
| 3 **面积／体量** | 谁占大头、谁的盘子大 | 块大块小、权重方块 |
| 4 **斜率／角度** | 在涨还是在掉、跌得多急 | 折线、趋势箭头、斜切、坡度 |
| 5 **明度／色阶** | 风险几档、哪个更严重 | 深浅、灰阶、热力、色带 |
| 6 **形状／图标** | 这是什么类型、什么来源 | 形状自带语义（圆／方／角／符号） |
| 7 **连接与包围** | 这些是一组、谁和谁有关 | 分组框、连线、从属缩进 |
| 8 **时间与节奏** | 什么时候、连续几天、什么时候冲突 | 时间轴、刻度、区间、间隔 |
| 9 **大小与字重** | 这一屏最重要的是哪个 | 同字号下用字重／深浅／留白分层 |
| 10 **动效与变化** | 刚刚发生了什么、正在变的 | 出现方式、脉冲、状态切换 |

**规则**：

- 每个方向选 **1–2 个主通道**当"当家"，其余做辅助；
- **同批方向的主通道组合不得重复**（A 用「明度＋位置」，B 就不能再用这一组）；
- **同批方向的主容器不得同族**，**表格／网格类容器在一批里最多出现一次**；
- 每个方向必须写明：**"掉多少"用什么通道 / "谁先做"用什么通道 / "风险几档"用什么通道**；
- 通道要配得上信息：**数量用长度或面积，趋势用斜率，档位用明度，顺序用位置**——别用位置表达数量，也别用颜色表达顺序。

|---|---|

## 9 · 硬性要求

1. **不改业务语义**：信息、数字、状态、按钮名按 §3 照做；**表述可以压缩改写**，语义不得增删。

6. **中文排印是硬指标**：多行标题、正文、窄屏换行必须在真实阅读尺寸下成立，不靠缩字号硬塞。

## 10 · 路径与自检：先骨架，后上色

### 阶段一（骨架，只准用黑白灰）

1. 认品类、拆 2–3 个标杆——记下"它用什么通道表达了什么"（§1.2）。
2. 按 §7 起 3–5 个方向，**每个方向先写一句主通道声明 ＋ 十个板块各一行主张**（§2.3），再画骨架。**先别管好不好看——先确认每一块你都有话说，而且至少有两块不是常规做法。**
3. **骨架一律黑白灰**，这一阶段禁止出现任何有彩色。
4. **两道并排自检**：灰度骨架并排（像同一页的几套配色 → 重做）；缩略图并排缩到约 100px 宽（认不出是不同的图 → 重做）。
5. 填九轴表，核对"至少 3 轴不同且含轴 1 或轴 2"；核对主通道组合不重复、主容器不同族、表格/网格最多一次。

### 阶段二（上色，一次只做一个方向）

6. 逐个上色，**不要在同一份文件上叠改**；每做完一个再做下一个。
7. 按 §3.0 把长句换成通道的表达，核文字预算（≤ 700）。
8. 截图取证：首屏、200% 局部、P13 延展；中文换行必须真的看过。
9. 出对比页（三行：缩略图 / 灰度骨架 / 上色），给推荐。

### 交付前的十项自检（逐条过，写进 README）

1. **缩略图测试**——约 100px 宽并排，认得出是不同的图吗？
2. **删 CSS 测试**——把样式全关掉，两个方向的骨架还像同一个页面吗？
3. **汉字计数**——整屏正文 ≤ 700？每张卡正文 ≤ 2 行 × 24 字？
