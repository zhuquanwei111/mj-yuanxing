## 一、三条症状，都有量化证据

### 1. 换色游戏（不是感觉，是事实）

把 CSS 全部删掉、只比 DOM 结构（标签+类名余弦，1.000 = 一模一样）：

| 模型 | 方向对 | DOM 余弦 |
|---|---|---|
| GPT | d1↔d2 / d1↔d3 / d2↔d3 | **1.000 / 1.000 / 1.000** |
| GLM | d1↔d4 / d2↔d4 / d1↔d2 | 0.932 / 0.968 / 0.945 |
| GLM | d1↔d3（唯一动了结构的那版） | **0.821** |

GPT 三份连文本分布都完全相同（1996 可见汉字、44 逗号、11 句号、19 个句子块）——**一份标记 + 三套 CSS**。

### 2. 上一版污染下一版

- 八份产出 **8/8 都是浅底**（亮度 0.93–1.00），没人试深色或中间调。
- 同模型方向之间的**色相家族**重合 3–5 个。GPT 最典型：d1 青 → d2 黄绿 → d3 蓝，但 **橙/琥珀黄/红/绿四个家族三版都没走**——被换掉的只有主色，功能色被当成常量留下来了。
- 每份还有 **4–17 个没声明成变量的硬编码色**，在版本之间搬运（GLM d3→d4 共享 `#e8b93b`）。
- 机制：同一个对话里连续做多个方向，模型复用自己刚写的标记与变量。

### 3. 文字墙

| | 可见汉字（一屏） | 相对规格 | 规格里 16 条长句原样保留 |
|---|---|---|---|
| 规格要求 | 1389 | 1.00× | 16/16 |
| GLM d1–d4 | 1340–1384 | ≈1.0× | 4/16 |
| Kimi d1 | 1276 | 0.92× | 4/16 |
| GPT d1–d3 | **1996** | **1.44×** | 3/16 |

两家把长句**重写扩写**，而不是把句子变成控件。唯一反向做的是 GLM d3（泳道那版）：DOM 相似度最低、色相家族最多（7）、饱和度最高（0.68）——**唯一一次真设计，正好是唯一被记住的那版**。

## 二、责任分账

**任务书这边的账（主要）：**

1. 写了"文案与数字照抄、一个字不要改"，等于**禁掉了设计师最该做的那件事**：把句子压成字段、标签、数值、图形。GLM d3 是唯一敢"违规"的，结果它最好。
2. "九条可拉开的维度"是**平铺清单**，没权重、没门槛。配色成本最低、最容易自我说服，模型必然走它。
3. 把"红=风险、琥珀=待跟进、绿=正常"写成必须保留的语义，被理解成"这些颜色不能动"，于是只换主色。
4. 内容规格以"逐句照抄"的形式给出，本身就把一屏 1300 字钉死了。

**模型这边的账：**

5. 结构差异成本远高于配色，不设门槛就不做（GPT 直接同一份标记换三次色）。
6. 默认审美偏浅底 + 柔和卡片，8/8 撞同一个套路。
7. 同一对话内连续产出，上下文共享导致串味。

## 三、下一轮立的规矩（已写进任务书 v2）

| 规矩 | 治哪个症状 |
|---|---|
| 一次对话只做一个方向，新方向从空白文件开始 | 串味（症状 2） |
| 文字预算：整屏正文 ≤ 700 字，每卡 ≤ 2 行 × ≤ 24 字；语义不变、表述可压 | 文字墙（症状 3） |
| 先交灰度骨架并排图，再上色；"看起来像同一页的几套配色"就重做 | 换色游戏（症状 1） |
| 结构差异门槛：九轴表至少 3 轴不同，且必含"信息骨架"或"首屏主角" | 换色游戏 |
| 同批方向共用色值必须为 0（黑白灰除外）——**功能色也要一起换** | 串味 + 换色游戏 |
| 配额：至少 1 个深底、1 个零彩色、1 个信息图形化 | 默认审美趋同 |
| 给出"句子 → 控件"转换示例（这是教具，最有用的一条） | 文字墙 |
| 禁用清单：深色底紫渐变玻璃卡、圆角+投影通吃、emoji 当图标 | 默认套路 |
| 标杆拆解改成"它把哪句话变成了什么控件" | 空泛的方向声明 |
| 不要读上一轮任何候选产出（`gpt-*` / `ds-*` / `kimi-*` / `glm-*`） | 全部 |

一句口号，写进任务书了：**能用数字、标签、图形回答的，不要用句子回答。**

# 第二轮（任务书 v2）复盘：格子收敛

## 症状

三个模型在"减少文字"这件事上，**绝大多数只会用格子**（横格、竖格、表格），布局也趋同——同一个毛病换了个样子回来。

## 病根：还是任务书

1. **我给的三个"句子 → 控件"示例，全是同一种编码**（字段／标签／数值：`22:00-01:00` ｜ `同档 2 个大场分流` ｜ `−42%`）。模型照着示例学，学到的就是"排成字段格"。
2. **我给的"骨架候选菜单"11 项里有 8 项是格子家族**（清单／分栏／泳道／看板列／收件箱／表格化／网格热力／卡片+图标）。菜单本身就有格子偏向，模型挑来挑去都在同一族里。
3. **文字预算 ≤700 这条压力天然偏向格子**：格子能装很多条目、字又少，是满足预算的"最省力解"。我给了压力，却没给压力之下的**替代通道**。

模型侧的账：在"少字"约束下，格子是最安全的选择（可读性最有保证、结构最不需要勇气）。**不点名别的通道，它不会自己走过去。**

## 新规矩（已写进任务书 v3）

| 规矩 | 治什么 |
|---|---|
| **主通道唯一**：每方向只选 1–2 个主编码通道，同批组合不得重复 | 三个方向都排格子 |
| **容器不重复**：同批主容器不得同族，**表格／网格一批最多出现一次** | 横格竖格各来一版 |
| **缩略图测试**：缩到约 100px 宽并排，还得认出是不同的图 | 格子内部换花样也算过关的漏洞 |
| **"骨架菜单"换成"编码通道菜单"**（10 个通道，各自写清擅长回答什么） | 菜单本身的格子偏向 |
| **§3.0 改为"同一句话的六种画法"**（字段／长度／明度／斜率／时间／位置），做成对照表 | 只教了一种编码 |
| **八项交付前自检**：缩略图／删 CSS／数汉字／比色板／比通道／swap／signature／配额 | 让不合格方案在交付前暴露 |
| 从 interface-design 抄来两条免费自检：**swap 测试**（换成最普通的字体和布局，还有区别吗）＋ **signature 测试**（指出五个具体位置上的签名元素，"整体气质"不算） | 方向缺少可指认的记忆点 |

## 追加判定：只有一块出彩，也算不合格

泳道那版（glm-d3）之所以被记住，恰恰说明其余板块是**默认样子**——KPI 四个等大格子、顶栏 logo＋标题＋铃铛、底部五个文字 Tab，全都没动脑子。
**一个板块好 ≠ 这一页好。** 所以 v3.1 把评审单位改成**板块**：十个板块逐个看，哪一块写不出主张就是没做完；并且要求至少两块大胆到「一眼认不出是常规做法」。

责任分账补一条：**门槛密度过高也会压出"守规矩的保守卷"。** 所以 v3.1 明确写了「这些门槛是底线，不是上限；底线之上的空间全部留给你冒险」，并列出可牺牲项（非常规排版带来的一次性学习成本、略多的动效）与不可碰项（AI 三态、文字预算、数字准确、手机形态、40px 命中区）。
