# Implementation Plan：明镜手机原型体验改版 V3

状态：已获需求方批准，Codex 正在直接执行。最高目标是优秀、清晰、可信的手机原型体验；既有页面数量、文档结构和当前布局都可按用户任务证据调整。本计划取代 V2 计划的剩余事项；旧执行记录保存在 tasks/history/，浏览器证据与覆盖台账继续保留。

## 目标与范围

把现有单文件 HTML 手机原型重新组织为角色可理解、任务优先、路径可预期的产品界面：用户一进入页面就知道当前任务、对象、状态和下一步；完整业务信息始终有清楚的查看路径；不再依靠密集卡片、超小字、标题折叠、横向拖动或层层弹窗承载信息。

覆盖全部 49 个现有入口（47 个编号页、AI、角色 MY）与 34 个弹窗调用。每个入口可保留、合并、重做、移除或按任务证据新增；历史 hash 深链有明确去向。P30 的两句业务文案“回访第一：情绪、结业、激活三类今天必须碰”和“主播留存的第一道防线”必须保留在产品页面并清楚可读。

只改手机产品体验及必要的原型评审预览支持。桌面产品、后端/AI能力、业务规则/数据口径、真实服务接入与生产发布不在范围。

## 设计方向

方向采用规格批准的“直播运营信号台”：以主播、直播时段、风险信号、回访、任务交接、结业和账期为产品语言，用“对象 → 时间/状态 → 下一步动作”构成列表与详情的共同语法。视觉重点放在一条当前最重要的工作信号；其余界面安静、成组、有序。

基础色板：设备画布 #F4F6F8、内容表面 #FFFFFF、正文墨色 #18212B、辅助文字 #617080、品牌蓝 #315BCB、结构线 #DCE2E8。风险红、提醒琥珀、完成绿仅用于对应业务状态。中文使用系统字体栈；页面标题 22px、区块标题 17px、正文 15px/1.55、非关键辅助信息 13px。4px 基础间距；组内 8–12px、区块间 20–24px。主要动作高度 48px、所有常用触控区至少 44×44px。拒绝无语义渐变、套卡片、所有 KPI 同权、只靠装饰标签表达层级。

页面骨架方向：
页面标题与当前任务 / 明确的同级分段视图
当前优先信号（对象、原因、时限、状态、一个主动作）
有序列表或步骤（主内容）
次级概况与历史通过直接命名入口
固定的角色顶层导航（不放页面动作）

不要照抄附件参考图或通用 SaaS 模板。选择性借鉴其清晰标题、列表→详情、状态表达和进度组织；按明镜业务对象重新构图。

## 执行原则

- 按增量纵向切片：每任务完成一个可独立查看的完整路径，运行针对性检查、浏览器点击和截图后再推进下一任务。
- 先 IA，再共享视觉/交互模式，再逐角色路径；全程优先解决结构与信息顺序，不以加间距或调字号冒充改版。
- 业务文案、状态、风险、时间、金额、结果、必要帮助不按“小字”一刀切删除；只把评审元信息移出手机画布。指定 P30 两句保留。
- 主要内容默认可见或有明确命名入口；主要导航不用标题下拉。所有字段能在手机单列路径中完整查看，不让整页横向滚动。
- 每次修改先记录目标路线与视口；修改后截图自评并检查布局、焦点、键盘、返回恢复和浏览器日志。已有 V2 截图只作基线，不冒充 V3 验收。
- 单一 HTML 是高变更风险区；小步修改并保持每个增量可运行。未经确认不改业务规则、计费、AI能力或真实服务行为。
- 不使用 ZCode 委派；本轮由 Codex 自主拆分、实现、审查与验证。

## 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 页面合并令旧入口失效 | 用户/评审无法跟进原路径 | 建立旧 ID 到新视图的映射，保留有意义的 hash 深链 |
| 只改 CSS，主次仍混乱 | 界面仍像堆叠卡片 | 每个页面先确定核心任务、对象、主操作和次级入口，再实现布局 |
| 信息裁剪损伤业务引导 | 用户看不到完成任务所需依据 | 每项删改记录信息新归属；P30 两句保留在产品画布 |
| 全局样式影响多角色 | 旧页面回归 | 每个共享模式完成后检查代表角色，再批量应用 |
| 弹层/软键盘压住动作 | 流程无法完成 | 弹层按手机视口限制，长编辑全屏内滚动，短屏与键盘状态实测 |
| V2 记录状态冲突 | 误报已验收或重复返工 | V2 状态只作历史记录，V3 用独立任务状态与新浏览器证据 |
| 单 HTML 改动过大 | 回归定位困难 | 每个增量仅改一个路径组，修改后立刻跑脚本和浏览器检查 |

## 增补：组件库接入与路由层级复核（T16）

这是用户批准 V3 执行后的追加工作线，不代表阶段 D 的浏览器验收 T15 已完成。目标是用适配现有纯 HTML 的移动组件库统一重复交互，同时重新检查路由深度；有证据才改路由，避免为迁移而迁移。

### T16 工作拆解

1. **选型与边界：** 比较可在当前无框架 HTML 中使用的组件库，确认许可、离线加载、体积和主题方式；记录组件库不负责解决 IA 的边界。
2. **精简本地组件基础：** 只打包第一批高复用控件，禁止运行时 CDN；把控件接到共享渲染入口并保留原页面业务动作。
3. **分组选项降级：** 选项数量少时用分段控件；选项很多时改为完整可见、可换行的原生按钮组，不做横向滚动或选项下拉。
4. **路由深度审计：** 检查 49 个兼容入口、角色导航、详情返回和重复视图；只有存在多层绕行/重复页面证据时才调整，并保留旧 hash 映射。
5. **逐模块扩展与验收：** 只在浏览器证明尺寸、焦点、键盘和状态行为无回归后扩展到按钮、表单等类别；弹层最后单独评估，不能直接替换现有焦点管理。

当前进度：共享分段已接入 Ionic；首轮控件审计修正了两个 40px 操作按钮、筛选下拉字号/高度和 toast 的过时紧凑高度规则；四类页签改为换行布局，并清除产品画布残留的横向滚动规则。未发现值得全站替换原生按钮或表单的证据；浏览器中的实际点击区域与窄屏折行仍由 T15 验收。

本轮组件选型为 Ionic Core 9.0.7；执行进度与验收边界更新在 `tasks/todo.md` 和 `tasks/ui-component-library-decision.md`。路由源码复核发现路径为平铺页面 ID 加最多一级对象 ID，现有页面取舍映射已明确来源/返回点，因此当前没有足够证据重写 URL 层级；这不阻止后续根据用户任务路径合并重复视图。

## 增补：业务保真下的全原型视觉精修（T17）

**状态：** 2026-10-10 已拆解，尚未开始实现。此增补承接当前 V3 原型，不覆盖 T1–T16 的完成记录；遵循需求方最新约束：完整保留现有业务功能、页面信息架构、跳转流程、业务文案和演示数据，不新增虚构业务模块，不以视觉统一为由改业务逻辑。若旧设计文件与本增补冲突，以本增补为准；历史文件保留作决策记录。

**实现边界：** 产品入口仍为单文件 `明镜/1_产品原型/明镜产品原型.html`（约 6,981 行），CSS 由多个历史覆盖块组成；先定位层叠关系，再小范围合并规则，禁止整文件重写。原型还加载 `vendor/ionic/ionic-primitives.min.js`，与最新“纯 HTML/CSS/原生 JavaScript、不引入第三方库”约束冲突，需要以原生控件替换其实际用途后再移除引用。保持本地静态打开兼容；只触及本任务必要文件，不纳入工作区既有无关改动。

### 保护基线

- 49 个现有入口、34 类可见弹层、路由与返回语义、现有按钮处理器、权限、文案和数据均为保护项；改前后用现有脚本、路由和业务测试核对。
- 页面与内容表面使用白底；中性色用于文字、描边、分割线和禁用态，不使用大面积灰色铺底。风险状态采用文字、圆点或图标，不依赖颜色，也不保留左竖条。
- 不把全部记录改成卡片：聚焦任务可使用单一重点容器，普通列表使用统一行高与分隔；同一业务对象在概览中显示摘要，在明确详情入口显示完整依据与处理过程。
- 核心提交/确认动作可用实心按钮；导航、查看和已有文字式动作按语义呈现。不得一概去按钮，也不得把已有文字入口一律改成实心按钮；P20“去复盘”样式按需求方确认的历史设计执行。手机按压/焦点状态须可见，桌面 hover 只作补充。
- 筛选标签保持完整且可横向滚动，不截断业务类别。隐藏原生滚动条时，触摸/滚轮滚动与边缘提示仍须可用。
- 不编造业务数据、虚假加载过程或对话内容。头像优先复用仓库本地素材；没有素材时使用一致的姓名首字占位。
