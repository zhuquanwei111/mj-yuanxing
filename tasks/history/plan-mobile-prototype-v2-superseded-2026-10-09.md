# 明镜手机原型视觉与交互整理计划

日期：2026-10-09。用户已确认：先整理现有手机端，桌面布局后续再做。T1–T8完成后，用户进一步明确：页头目标/价值说明、角色讲解、AI能力分工等制作性小字都不能出现在手机产品界面，统一放在原型评审侧栏；当前按此标准完成T9修订。真实软键盘及其他限制见覆盖清单。执行与验证记录见[实施记录](implementation-log.md)。

后续复核新增的信息架构与交互清晰度改版按[手机原型信息架构规格 V2](spec-mobile-information-architecture-v2.md)执行评审；逐页依据见[49个入口复核矩阵](page-by-page-mobile-design-review.md)。前者定义系统方案与任务，后者记录每页的现状观察、布局建议、参考图取舍及证据边界。本轮仅形成指导规格，未修改原型实现。

## 目标与边界

把原型整理成“先看重点、直接操作、返回不迷路”的手机工作台。审查依据为原型HTML与已记录的截图/浏览器证据，完整问题与页面分组见[审查报告](visual-interaction-audit.md)。按下列顺序逐项实施；没有验证通过的项目保持未完成。

范围：手机布局、文字层级、默认信息量、导航上下文、表单保留、弹层、反馈、页面动作，以及原型评审用的外围目录与说明栏。外围说明栏服务于原型评审；桌面产品工作台、后台、数据计算、AI能力、真实服务接入及其他非界面问题仍暂缓。

覆盖整个HTML：46个注册页面，补充AI、P41D学员档案、MY各角色个人页及既有动态状态；34处弹窗调用与通用提示。逐项状态见[全原型覆盖清单](page-coverage.md)，源码盘点不等于逐页浏览器验收通过。

## 已确定的设计决策

- 保留角色工作台与已有有效业务信息，不把所有角色合成一个菜单。
- 页头页面目标、适用角色、价值说明、AI能力分工与制作备注均放外围评审侧栏；P30“回访第一：情绪、结业、激活三类今天必须碰”和“主播留存的第一道防线”也按用户最新要求移至侧栏。
- 手机页面只显示用户完成任务所需的业务内容：真实状态、风险、时间、金额、AI生成结果及操作结果保留；解释界面为什么这样设计、AI/人工如何分工的说明移至侧栏，不按字号删除业务信息。
- 原型评审采用“左侧角色/页面目录—中间手机预览—右侧当前页说明”。右侧承载适用角色、设计说明、主路径和演示限制，不重复挤占手机内容。手机访问时收起外围区域，产品按可用宽高展示。
- 所有弹窗、遮罩、底部面板和轻提示限定在手机内容视口；简短确认与少量选项居中、长编辑采用手机内全高面板，不额外增加路由层级，长内容可滚动且关闭/主操作可达。
- 保留黑白基调，以文字重量、组间距和布局表达主次，颜色只辅助表达状态。
- 一个页面明确一个主任务；资料、依据、历史、配置按需访问，入口可发现。
- 新页面从顶部开始；返回恢复完整来源路由、对象、页签、筛选和滚动位置。
- 先验证手机容器、弹层和文案分类的公共模式，再证明老板、运营、主播三条路径顺畅；P30用作“产品页与评审说明分开”的示范，最终覆盖全部角色与页面。
- 源码推断与实际显示/点击证据分开记录；HTTP预览通道已于2026-10-09验证可用，首轮结果见[浏览器实测记录](browser-validation.md)。

## 依赖与执行纪律

依赖关系：T1→T2→T3；T4依赖T1/T2；T5依赖T4；T6/T7依赖T1/T2及检查点B的稳定模式；T8依赖前七项。所有任务都可能修改同一HTML，按顺序执行，不并行编辑。

每个任务是一个完整、可查看的界面路径，完成后立即验证；不能先整页批量换样式再检查。实施时遵守仓库提供的ZCode路由要求，本次审查与计划没有实现代码的委派或修改。

## 风险与控制

| 风险 | 控制 |
|---|---|
| 只加间距导致长页更长 | 同时压缩默认说明、分离历史/配置，优先解决结构。 |
| 隐藏信息后找不到 | 每个收起内容有命名明确的入口和状态/数量提示。 |
| 合并确认误改业务 | 保留必要人工判断及既有回传规则，只改变界面呈现和动作组织。 |
| 通用样式修改影响12个角色 | 每任务检查所改页面与一组代表页面，最终逐角色补齐。 |
| 把业务信息误当成制作说明移走 | 逐页记录文案分类；保留任务所需的状态、风险、结果和动作，页头目标/价值及AI人工分工说明只放侧栏。 |
| 只调整字号，卡片仍被多按钮挤压 | 同步调整列宽、换行、操作区与信息顺序，特别核对P31姓名逐字竖排等问题。 |
| 只修一个弹窗，其他调用仍越界 | T1先修公共容器；各角色任务复核实际内容；T8按34处调用逐项收口。 |
| 把外围评审壳当成桌面产品改版 | 外围只提供目录、预览和说明；手机产品范围与既有业务流程保持明确。 |
| 来源恢复错误 | 使用完整路由与对象键，按实际往返路径检查，不能只测模块首页。 |
| 预览服务或浏览器访问中断 | 当前用户提供的HTTP服务可用；若中断则保留原文件和未验收状态，恢复后再继续，不能宣称通过。 |

## 待复核的设计细节

- P13优先露出哪些既有今日数据；不得为布局填入新造的业务数值。
- “确认并发送”是否覆盖每条路径的必要确认；有独立留存用途则保留“暂存草稿”。
- 合并P83与AI后，保留主播常用问题与现有业务卡入口。

这些细节已在T1–T8具体界面与路径中复核。当前页样式与实测结果见实施记录及覆盖清单。

## 此次修订的验收基准

- 三种手机尺寸为360×800、390×844、430×932，并补短屏/长内容/输入键盘场景；手机界面无整页横向溢出、文字逐字竖排或被遮挡的操作。
- 正文14–16px，辅助信息12–13px，必读文字使用清楚的文本色；主按钮及图标点击区域以44px为目标，不能靠缩字塞入多列。
- 页头只保留产品页面本身的标题；目标、角色、价值、AI分工和制作说明只在评审侧栏出现；手机界面保留完成任务所需的信息。
- 弹窗位置与大小以手机内容视口为边界；遮罩不覆盖外围评审侧栏；长内容内部滚动、主操作可达，关闭后恢复触发项焦点与页面位置。
- 参考站点已成功访问并截图，先前读取超时不视为网站不可用；借鉴外围结构，不照搬固定手机高度。证据见[浏览器实测记录](browser-validation.md)。
