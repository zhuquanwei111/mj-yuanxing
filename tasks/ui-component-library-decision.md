# 手机原型 UI 组件库选择与接入边界

日期：2026-10-10。范围：明镜单文件 HTML 手机原型，运行时无 React/Vue 应用框架，旧路由与可离线评审能力需要继续有效。

**当前状态（2026-10-11）：** 下方 Ionic 采用决策为历史记录，已由 T17.4 的原生控件方案取代。产品 HTML 当前不加载 Ionic runtime，也不含 Ionic Web Component 标记；vendor 目录暂保留，但没有运行时引用。

## 决定

采用 **Ionic Core 9.0.7（MIT）作为选择性移动交互组件库**，不把它当作全站视觉模板。首批接入 `ion-segment`、`ion-segment-button`、`ion-label`，统一同级视图切换的键盘、触摸和选中态；其余页面骨架、列表、对象卡、业务按钮和现有弹层继续按明镜的业务语法设计。达到 5 项以上的选项不压进窄分段控件，改用可换行的两列原生按钮组。真实浏览器曾复现指针点击没有更新视图，因此为该控件增加事件委托适配和显式 `aria-selected`，而不是把组件自带的 change 事件当作唯一输入路径。

组件通过 `明镜/1_产品原型/vendor/ionic/ionic-primitives.min.js` 本地 classic script 加载，不走 CDN、不要求开发服务器打包；本轮精简构建约 87 KB，附带 Ionic MIT license。NPM 完整压缩包约 3.8 MB，解包约 20.8 MB，因此不复制整包。选择分段控件是因为它出现在十多个任务视图中，而当前手写分段逻辑虽有可见选中态，但键盘方向键、焦点循环和控件行为需要逐页重复验证。

## 取舍比较

| 方案 | 优势 | 不选/选择原因 |
|---|---|---|
| Ionic Core | 移动优先；Web Components 可用于纯 HTML/JavaScript；支持 CSS 变量主题；可以只打包需要的控件。 | **采用但限制范围。** 默认 iOS/Material 风格需要主题覆盖；不能把整套默认样式直接套到明镜页面。 |
| Vant | 手机端业务控件丰富，适合 Vue 移动应用。 | 当前没有 Vue 运行时；为使用组件而迁移整份原型，成本和回归面过大。 |
| Ant Design Mobile | React 移动组件成熟、覆盖面较广。 | 当前没有 React 架构；完整接入将迫使大规模重构，对单文件可评审原型不合算。 |
| 继续只用原生控件 | 体积最小、无需许可或第三方更新。 | 可继续用于长选项、特殊表单和弹层；但把重复分段交互逐页手写，难以保持一致与可访问性。 |

## 使用边界

- 组件库负责交互原语和常见状态；内容顺序、优先级、卡片结构与操作路径仍由页面任务决定，不能用“装上组件库”代替 IA 改版。
- 每批最多迁移一类控件和一组相关路由，先验证主题、中文长标签、触控尺寸、键盘操作和旧状态回写，再扩展。
- 暂不替换 `openModal`：现有弹层有手机画布约束、焦点循环、Escape 关闭与返回焦点行为。待 Ionic 弹层实测完全兼容后，再决定是否迁移。
- 不全站换成 Ionic 默认卡片或按钮；不引入 CDN 运行时、完整 Vue/React 栈或重复的图标包。
- 旧 hash 继续作为兼容入口。当前路径是平铺页面 ID 加最多一级对象 ID（如 `#P22/主播ID`），未发现需要通过改 URL 才能解决的深层路由；如后续 IA 审查证实多个屏幕重复绕行，再按任务合并视图并留兼容跳转。

## 其他控件的首轮审计（2026-10-10）

原型已有业务按钮、过滤项、页签、分段视图、底部导航、消息发送区和弹层操作的定制样式；多数共享按钮已统一至少 44px 高度。静态检查发现公会套餐按钮和平台排行行内操作被模块 CSS 降到 40px，现已恢复为 44px；toast 的动作按钮移除了过时的 24px 行内高度；共用筛选栏下拉框从 12px 调到 16px 字号并补齐 44px 触控高度；平台、学习、权限、入驻审核四类页签改为换行显示，不再要求横向拖动。移除失效的横向页签/表格滚动规则。确认唯一 `<details>` 折叠位于评审侧栏的 AI 分工说明，产品画布没有标题折叠业务内容。新增 `tasks/control-target-size.test.mjs` 防止这些规则回退。

首轮结论是不批量迁移现有按钮：原生按钮具备明确的业务语义、禁用态和定制布局，当前证据只支持修复少数尺寸例外，不支持全站替换为 `ion-button`。共用表单与消息输入已有 16px 字号/44px 触控高度，只有筛选下拉框需要补齐；不再为使用组件库而迁移原生控件。弹层迁移仍需先完成真实浏览器的短屏、焦点与关闭行为测试。源码规则已静态验证；代表分段控件也已做真实鼠标点击检查，但触控区域测量和多尺寸验收仍列入 T15。

## 尺寸与键盘续验（2026-10-10）

分段控件重绘后焦点丢失已在真实浏览器复现并修复：原事件处理同步替换选项节点，直接对自定义元素调用focus不会聚焦其内部按钮。现在处理器在下一帧调用Ionic ion-segment-button.setFocus()；非Ionic的长选项按钮仍使用原生focus。单测7/7及全量70/70通过。

P20在320×568、360×800、390×844、430×932、360×480截图查看；方向键、Space、正文更新、选中样式和重绘后焦点均通过。P30在320×568完成方向键/Space及焦点复核。P41五项原生阶段选项在320×568两列换行，Tab、Space、结果更新和焦点保持通过。全路由初始态245组尺寸测量未发现横向溢出；截图已查看但未归档。T15其余路由状态与弹层回归仍未完成。
