## 1. 使用的设计技能

- `frontend-design`：先按「直播公会日常运营 / 主播行动」形成设计方向——签名元素为**行动队列行**（对象 + 原因 + 状态 + 一个动作，状态用左侧 3px 色条）；形成 token 与代表页线框；逐条列出拒绝的默认布局（四张等权 KPI 大卡、同款圆角卡片堆叠、`<details>` 折叠承担主业务区、宽表格横滑、卡片内并排多按钮、装饰性渐变/彩色图标砖）。全部落在 [设计基线](design-baseline-mobile-v2.md)。
- `interface-design`：编码前检查既有原型组件与样式约束（`.card/.btn/.badge/.kpi/.ptabs/.analysis-panel` 与 v5 黑白覆盖层）；对重复控件统一尺寸与状态；为手机列表行、分段视图、更多操作面板、长字段定义行为；补齐默认/按下/焦点/禁用/完成反馈。项目内不存在 `.interface-design/system.md`，本轮的 token 与控件规格记录在下方第 5 节，未自动写入仓库长期规则文件。

## 3. 逐模块改动

### V2-2 运营 P20 / P21

- **P20**：改为「班次 → 待办主线 → 今日概况 → 今日开播」。待办按紧急度排序（有风险 → 待跟进 → 人工记录 → 待分析/草稿），第一件用焦点记录完整呈现（含摘要要点与草稿正文），其余进队列行，行内动作命名清楚、完整内容与全部动作落在条目面板。原来的四张同权 KPI 大卡改为可下钻概况条并移到待办之后；群发回执从待办首位改为班次下方的持久状态行（可展开逐人回执）；今日开播补齐搜索与状态筛选（全部/在播/未开播/有风险 + 结果数）。
- **P21**：标题下并列「主播名单（人数）」与「主播动态（待处理数）」两个分段视图，原来的 `<details>` 折叠动态已删除。名单行给出姓名、赛道、直播状态与该主播最相关的一项指标，行内只留一个常用动作（发消息），其余操作进入详情。动态改为事件时间线：事件类型、主播名、时间、当前状态齐备，按「待处理优先、再按时间」排序，每条带「处理/看档案」直达入口，并有「待处理/全部」范围切换。切视图保留搜索与筛选状态（已验证），从动态进详情再返回仍在动态视图。

### V2-3 主播 P80 / P22

- **P80**：首屏只有一项「现在最该做的一件」（19:30 画面自检），含进度 0/6、六项勾选与唯一主按钮；主按钮落到下一项未勾选项。其余内容降级为「今天还有 N 件事」（今晚完整安排 → P81、昨晚成绩与复盘 → P82、公会派的活、独立/会员态）与「提醒」。勾满六项自动回传公会，焦点卡与文案同步翻转。原「今晚完整安排」不再藏在折叠区。
- **P22**：对象头改为身份 + 业务状态 + 风险 + 关键值 + 数据时间范围，操作收敛为**一个主操作（随状态变化）+ 一个常用次操作 + 更多操作**。主操作按状态计算：有风险 → 去复盘；无开播数据 → 生成首播规划；其余 → 生成规划。四个平铺按钮（生成规划/转交/记沟通/发消息）不再挤在资料卡里；数据是「趋势」视图，趋势视图同时保留 AI 解读与引用明细。原来的三页签 + 二级 chips 改为四个同级视图：**概况 | 趋势 | 规划与复盘 | 协作记录**。每页暂无数据的记录不再并入主播指标卡，而是进入时间线并列视图。资料与成长阶段移入「概况」，不再依赖 `<details>`。切换主播时视图回到「概况」，不继承上一个对象的选项（已验证）。

### V2-4 培训 P40 / P41 / P41D / P42

- **P40**：顶部用四项摘要标识（待带教 / 待评分·需补考 / 临近结业 / 本月结业），主体先给焦点记录（结业评估最近），再给带教队列，最后是命名入口（学员名单与成长任务、带教与考核、课目配置）。原来的「在训新人」折叠区与四张等权 KPI 已删除。
- **P41**：顶部「学员」分段导航 + 「成长任务 / 课目管理」视图切换；当前学员的姓名、第几天、阶段、进度与卡课状态固定成一屏可见的对象条；「当前应完成」用焦点记录给出课目、状态与**培训师验收动作**，任务清单按训练阶段（全部 / 第1-3天 / 第4-6天 / 第7-10天 / 第11-15天）分段筛选并带数量；课目配置成为独立命名视图，改名入口保留。
- **P41D**：对象头（阶段、进度、考核条数、结业状态）+ 任务进度 / 考核成绩 / 沟通记录 / 结业证书分区，全部不再折叠。路由改用主播 id，返回任务页会保持同一位学员（已验证）。
- **P42**：默认视图是「待评分 / 需补考」队列，第一件用焦点记录，其余进队列；「全部记录」是同级视图，含逐条记录、考核明细（原表格转为每位学员一条纵向字段记录）与薄弱点。打分面板绑定学员与课目，判定后队列推进、状态持久可见；结业评估改为与新增结业任务联动（详见第 4 节的口径说明），并通过后自动转运营。

### V2-5 组务 P94

三个并列视图「待处理 / 本组成员 / 本组数据」，默认进入「待处理」。待处理队列把总监下达、主播风险、脚本待审、任务分配回执放在同一条按紧急度排序的队列里，每条带状态、负责人/下一步与一个可执行动作或完整动作面板。「分配任务给本组主播」是明确的整行主按钮；保存后回执立刻出现在待处理队列（已验证），并在主播沟通记录里留痕。「本组成员」给出全员名单（姓名、赛道、直播/风险状态、负责人与任务状态），可筛选（全部/在播/未播/有风险）并直达档案，不在折叠区里。「本组数据」以今日音浪为主、人数/在播/开播率/环比为辅，并写明统计周期与口径。原来塞在首页的跨组对比与全公司速览不再属于本页（仍属 P93）。

### V2-6 全原型扫描

- 4 处原生 `<details class="analysis-panel">` 全部改为命名分区（共 20 个面板：P13/P23/P24/P30/P30D/P31/P50/P51/P61/P62/P70/P81/P93/P95/P96 等），手机界面内已无原生折叠承载业务区；评审侧栏的能力分工说明仍保留折叠，属于外围。
- 3 张宽表格全部改为纵向记录：P96 工具箱、P12 权限矩阵（可开启的字段保留点击开启与确认）、P03 公会用量排行（按规格 4.7 的字段模板）。手机界面内已无 `<table>` 与横向滚动容器。
- 交接中心 P25 的 35px 页签改为 44px 分段视图；会话列表预览不再用省略号截断；图表刻度从 7 个减到 5 个，避免窄屏刻度互相压字；窄屏下 `white-space:nowrap` 的指标标签允许换行。
- 队列行的行内动作统一为次按钮，整页只保留焦点记录一个主按钮（P20/P22/P40/P41/P42/P80/P94 首屏均只有一个主按钮，已逐页量测）。

## 5. 长期可复用的 token 与控件规格

已记录在 [design-baseline-mobile-v2.md](design-baseline-mobile-v2.md)，摘要：

- 表面 `--bg:#f7f8fa` / `--card:#fff`；文字四级 `--ink:#111827` / `--ink2:#4b5563` / `--ink3:#626c7b` / 辅助 12px；结构线 `--line:#e5e7eb`、`--line2:#f1f2f5`。
- 状态色只表状态：`--ok:#3F6212`、`--danger:#B91C1C`、`--warn-ink:#8a5a00`（文字）、`--warn-rail:#D9A441`（色条）。
- 文字层级：页面标题 18/650 · 区块标题 16/650 · 正文 14/400–500 · 辅助 12/400–500；数值 22–28/650 + `tabular-nums`。
- 间距基线 4px（4/8/12/16/20/24/32）；密度 workbench-tight；圆角 控件 10 / 记录 14 / 面板 18；**深度策略只用边框**，无阴影无渐变。
- 触控：所有可点元素 ≥44×44；队列行 ≥56；主按钮 44px 墨底白字；分段视图 44px。
- 视觉复核尺寸：360×800、390×844、430×932。

这些值是否作为后续会话的长期仓库规则，需由执行方确认后再写入 `.interface-design/system.md`；本轮未自动扩大仓库规则范围。

## 6. 验证与证据

- **静态检查**：`node tasks/check-prototype.mjs` 通过。
- **全原型扫描**：49 个已注册页面（含 AI、P41D、MY、P30D 与全部 P 页面）在 360/390/430 三个宽度下逐页量测，检查项与结果：

  - 元素越出手机内容框 = 0；文字被裁切 / `text-overflow: ellipsis` = 0；

  - 手机界面内原生折叠 `<details>` = 0；
  - 文案异常字样（`[object Object]` / `undefined` / `NaN`）= 0；
  - 文字小于 12px = 0；对比度不达标（正文 4.5:1、大字 3:1）= 0。
  - 三宽度 × 49 页 = 147 次页面量测，失败 0。
