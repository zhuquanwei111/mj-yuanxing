# Spec: mobile-visual-system

**Objective.** Give the multi-role live-operations product a distinctive, legible visual language that expresses urgency, time, object, and next action without generic card decoration.

**Direction.** Use a “live operations signal desk” grammar: time markers, roster identity, status/risk signals, handoff/action labels, and orderly event rows. Retain the current neutral white/gray base and brand blue as a single primary accent candidate; semantic red/amber/green communicate actual status. Remove decorative gradients, repeated shadows, and equal-weight nested cards unless a specific task justifies them. Distinction comes from purposeful hierarchy and data composition, not a borrowed consumer-app skin.

**Requirements.** Establish a compact token proposal for color, type, spacing, border, and density before implementation. Suggested type roles: 20–24px page title, 16–18px section title, 14–16px body/field label, 12–13px noncritical metadata only. Use 4/8-based spacing with visibly different intra-group and inter-group gaps. Long Chinese copy, names, money, and statuses wrap naturally. Product-required text must remain readable and accessible; reviewer-only copy is removed from the product surface by meaning, not moved by font size. Actions have a clear primary/secondary hierarchy and consistent states.

**Acceptance.** Apply the visual system to one representative screen per business domain, then check consistency without flattening role differences. A blurred/squint scan still identifies the page task and primary action. All content fits at 320–430 CSS px without reducing text to force fit. Primary controls target 44–48px visible height and 44×44px hit area where feasible; color and focus states are checked, not inferred.

**Boundaries.** Exact values remain a proposal until visual samples are reviewed; do not introduce a new brand identity or external font dependency without evidence.
