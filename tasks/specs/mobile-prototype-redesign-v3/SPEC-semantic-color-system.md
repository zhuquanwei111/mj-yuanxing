# 色彩落点筛选与实施记录

**状态：** C4、C5、C7 已采纳并应用；C1、C2、C3、C6 保持候选，等待用户筛选。  
**范围：** 在现有移动端原型的无色位置补充少量、语义明确的颜色，并提供同内容中性版与补色版供筛选。  
**当前约束：** 不使用紫色；不改已有色彩；不改变文案、业务逻辑、组件功能、布局或页面流程。

## 设计原则

1. 色彩只补在当前无色且确实能帮助识别的位置；如果实际页面已有颜色，跳过，不用新颜色覆盖。
2. 不设必须统一所有位置的单一强调色。当前选择、完成、正向数据、对标图表、待跟进、风险和内容结构分别使用适合其语义的色相。
3. 以文字、图标、线条和点作为最小处理单位。维持白色画布和黑色正文，不给整页、整行或整张卡片上色。
4. 所有方案先在对照页看效果。只有已采纳的 C4、C5、C7 写入主原型。
5. 色彩不单独承担状态含义；状态文字和原有操作保持不变。

## 实现范围与验证

主原型是单文件 HTML；已采纳的色位只通过局部 CSS 与现有标记类实现，不改业务逻辑、文案、组件布局或交互。修改前已有大量未提交工作，因此不做暂存或提交，也不整理无关文件。

验证命令：

```powershell
node tasks/check-prototype.mjs
node --test tasks/*.test.mjs
```

在浏览器中检查 P51 的待处理、处理中和完成三种状态，以及对照页的手机宽度换行和颜色落点。普通文字颜色需符合 WCAG AA 对比要求；颜色不能取代状态标签或图标。
