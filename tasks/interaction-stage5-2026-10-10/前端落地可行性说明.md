## 1. 项目现状与边界

当前是单 HTML 移动原型，含一套主样式、内嵌 Vanilla JavaScript、hash 路由/页面渲染、局部内存态，以及已随项目引入的 Ionic Core 分段控件。交互主要通过现有函数与行内事件执行。49 个路由的页面视觉覆盖和核心交互回归已经完成；样式修改仍集中在 HTML 的 `<style>` 中，不需要构建产物。

阶段五只交付行为规范与实现说明，不编辑原型 HTML、CSS、JavaScript，不更换组件库，不增加视觉或业务动作。进入实现时需保持：

- 所有现有按钮、图标、入口、文案、事件处理器、路由 hash 和业务状态迁移。
- 表单校验、角色/权限、草稿、筛选、分页/页签以及返回来源上下文。
- iOS/Android 共用的移动优先体验、黑白灰视觉和现有触控热区。
- 当前测试与浏览器基线；新动效不能通过删测试或绕开原有处理器“通过”。

### 当前技术事实

| 范围 | 已有实现/证据 | 对后续的影响 |
|---|---|---|
| 路由与返回 | `go()` 修改 hash，`hashchange` 调用 `render()`；`NAV_STATE` 保存来源页滚动、页签、展开内容，返回时恢复。 | 不要对每次 `render()` 播放整页动画；会让焦点、滚动和状态恢复更难稳定。 |
| 弹层语义 | `openModal()` 建立 `role="dialog"`、`aria-modal`、标题/描述、背景 `inert`；全局 keydown 管理 Tab 循环和 Escape；进出动效结束后恢复触发器。 | 共享 lifecycle 只延后清理，不替换业务 handler；关闭期间维持 inert、焦点限制和滚动锁。 |
| 底部面板 | `.sheetmask` 贴底；`.modal.sheet` 最大高度约82%，内部滚动并含底部安全区。 | 在同一边界补进出态可行；拖拽需新的 pointer/touch 状态机及真机误触测试。 |
| 编辑器 | `.modal.editor` 使用纵向布局、字段区独立滚动、关闭/动作区黏性定位；已有 P23/P24 等短屏、焦点和键盘路径测试。 | 软键盘可见时优先调整字段区可用高度；不要整体缩放面板或移动所有字段。 |
| Toast | 一个状态提示节点，带 `aria-live="polite"`，约180ms淡入/上移，3.2秒清除。 | 继续用真实结果文字；带操作入口的反馈要验证操作时长和聚焦可达性。 |
| 触控反馈 | 全局按钮/筛选/页签有按下或选中样式；`:focus-visible` 清晰；`prefers-reduced-motion` 已关闭转场/动画。 | 主要动作样式基础已具备，先补回归检查，不必重写按钮系统。 |
| 安全区与尺寸 | 页面使用 `100dvh`、底部 `env(safe-area-inset-bottom)`；原型在320–430px做过布局测量。 | Android/iOS真实系统 UI/软键盘仍需设备验证，不能以浏览器窗口值代替设备安全区。 |
| 自定义手势 | 源码未发现 `touchstart/touchmove/pointermove` 手势识别器；列表当前提供点击操作；分段关闭 swipe gesture。 | 不存在下拉刷新、左滑操作、面板拖拽；只有真实业务和交互清单批准后再增加。 |
| 异步数据 | 页面含本地样例态/模拟步骤，未以统一在线列表数据服务驱动所有页面。 | 下拉刷新需要后端或明确数据刷新函数；不能对静态样例做无意义刷新动画。 |

实现入口位置和行为证据见 [交互模式规格](../specs/mobile-prototype-redesign-v3/SPEC-mobile-interaction-patterns.md)、[浏览器验证记录](../browser-validation.md) 与原型 `openModal()`、`closeModal()`、`toast()`、`navigationView()`。

## 2. 各能力落地难度

难度用于安排后续实现切片，不是新增范围授权。

| 能力 | 可行性/工作量 | 前置条件 | 建议优先级 |
|---|---|---|---|
| 统一按压/选中/焦点反馈 | **高 / XS–S**；核心反馈已实现，主要是收敛令牌与补回归 | 不改行为；需覆盖所有按钮语义和 `prefers-reduced-motion` | P0：低风险收口 |
| 弹窗与底部面板淡入/位移 | **已完成 / S**；共享 overlay 使用 opening/open/closing/closed 生命周期、transitionend 与超时兜底 | 已处理重开取消旧定时器、关闭幂等、Escape/遮罩、减少动态和动画后恢复焦点 | P1：浏览器试点已验收；仍建议真机确认视觉节奏 |
| 页面路由转场 | **高 / S–M**；技术易做，收益未证明且可能破坏滚动/路由焦点 | 必须证明前进/返回方向、上下文保存与读屏落点不受影响 | P2：默认不加 |

| 底部面板拖动 | **中 / M** | 有明确“展开/收起/关闭”层级、抓手、滚动冲突策略、取消阈值、系统边缘测试 | 可选：先保留点击关闭 |
| 软键盘适配（浏览器） | **中高 / M**；`100dvh` 已有，可在有输入焦点时结合可见视口精调 | 真实 iOS Safari、Android Chrome 的 `visualViewport` 与滚动行为验证 | P1：做真机试点 |
| 软键盘适配（Android WebView） | **中 / M**；需确认宿主窗口如何传递 IME/system insets | Android 宿主配置、WebView 版本、是否 edge-to-edge；避免原生与 CSS 双重 inset | P1：宿主明确后实施 |

## 3. 推荐实现顺序

### P0：保持已有行为，统一测试基线

按真实组件盘点按压态、选中态、键盘焦点态、禁用态、错误/成功反馈。继续用 CSS 类/变量集中管理 140–160ms 反馈与减少动态规则。每条路径只调用既有 handler；点击后逐项检查路由、内存态、列表和消息结果没有变化。

### P1：弹层动效与键盘适配试点

1. **已完成**：在 P20 短操作面板与 P21 消息对话框验证共享弹层开合；CSS 采用 transform/opacity，关闭延后 inert 解锁和焦点恢复。
2. **已完成**：重复关闭幂等、重开取消旧计时器、Escape 与关闭按钮路径接入同一清理入口；减少动态偏好即时开合。
3. **设备待验收**：在真实设备聚焦长文本和靠近底部的字段，键盘出现时确保字段与保存/取消可达；键盘收起后恢复 scroll/context。只在确有遮挡问题时接入 `visualViewport`，resize 回调只更新必要尺寸，不整页 rerender，不清焦。
4. iOS Safari、Android Chrome、Android WebView、iOS WKWebView 分别记录设备/OS/viewport/键盘形式；物理键盘和模拟视口作为补充，不能代替软键盘验收。

### P2：先验证价值再做手势

若刷新与行操作出现真实用户需求，分别写独立小规格：目标列表、起始/完成/失败状态、触发阈值、无障碍替代、业务动作、数据源、返回和测试范围。下拉刷新绑定真正的数据重新拉取；左滑仅揭示显式按钮，滑动本身不执行删除、分派、发送等高影响操作。完成后逐角色检查纵向滚动、横向列表、日期条、输入文本选择与系统边缘返回是否冲突。

## 4. 原生 HTML/CSS/JS 落地注意事项

### 动画生命周期

- 入口/退出用显式 class/data-state，而非依赖在 `display:none` 与 `display:flex` 间直接切换后期待 transition 生效。
- 退出阶段继续保持 overlay 可见、背景 inert 和焦点环锁定；动画结束事件应校验当前状态，防止旧动画回调误关新打开的弹层。
- 同一弹层连续触发时先取消上一个动画回调；对状态操作加幂等保护。没有请求的按钮无需新增 loading 或延时。
- 动效优先 transform/opacity；避免滤镜大面积模糊、box-shadow 持续重算和逐帧布局属性。滚动列表只动当前卡片/面板，不动整屏。
- `@media (prefers-reduced-motion: reduce)` 必须将新增 transition/animation 归零或缩至非必要最小值；功能状态不可隐藏。

### 弹层和底部安全区

- `openModal()` 继续负责挂载、ARIA、焦点、inert 和滚动锁；CSS 负责具体时间、缓动、遮罩和位移。
- `closeModal()` 的业务关闭与视觉退出分层；所有关闭来源（关闭按钮、取消、Escape、遮罩、系统返回、hash 改变）共用幂等的最终清理入口。
- sheet 内长内容用独立 `overflow-y:auto; overscroll-behavior:contain`；操作区黏性固定但不能遮盖字段末尾。底部 safe-area 只由一个层级负责一次。
- 宿主 WebView 如果已经给网页容器加了系统 inset，网页不能再对同一部分重复加 padding。Android 官方文档明确提醒 visual viewport 会随 IME 调整，并指出 resize 清除焦点会导致键盘反复隐藏；接入时需与宿主一起验证。[Android WebView insets](https://developer.android.com/develop/ui/views/layout/webapps/understand-window-insets)

### 软键盘与视口

- 当前 `100dvh` 和底部 env 安全区规则继续作为基础，不把软键盘高度写成设备常量。
- 页面需按“有无输入焦点”处理可见视口，避免浏览器地址栏动画误判为键盘；必要时通过 `window.visualViewport` 观察高度变化，并用 requestAnimationFrame 合并单帧更新。
- 键盘 resize 时不得运行会清空当前输入、重置列表 scrollTop 或移除 focused input 的全页 `render()`；定向更新 CSS 变量/容器高度即可。
- 焦点字段靠近键盘时使用 `scrollIntoView({block:"nearest"})`，且不和用户滚动抢焦点；先确认浏览器原生滚动足够，再追加脚本。
- 字段根据内容使用 `type="tel/email/number/search"`、`inputmode` 和 `autocomplete`；密码/姓名等不强行锁定中文输入和系统联想。
- 真实设备检查键盘弹出动画、旋转、横屏/分屏、第三方键盘、关闭键盘、全屏输入和底部动作区，不重复扣除系统安全区。

### Gesture 事件

- 优先用按钮和原生 scroll。只有被批准的行需要手势时才局部加 pointer 识别；不要在 document/window 上写全局 `touchmove` 阻止滚动。
- 手势开始先记录 pointerId、起点和滚动容器状态；方向判定后只处理水平/垂直其中一轴；`pointercancel`、多指、控件选择文字、页面离开都要取消并复位。
- 只有阈值满足才切入揭示态，释放不足阈值回到原位；动作按钮单独点击才执行既有业务 handler。
- 列表同一时刻最多一个动作抽屉打开，其他行关闭；屏幕阅读器/键盘能找到对应按钮，按钮文字说明动作与对象。
- 下拉刷新应只在最上方、非输入状态、竖直运动方向明确时激活；快速多次释放只并发一次刷新；失败显示重试，不清掉旧数据。

## 5. 可复用测试与验收

### 自动检查

- `node --test`：仓库下既有行为、路由、键盘焦点、控件尺寸和阶段覆盖测试全绿。
- `node tasks/check-prototype.mjs`：内嵌脚本可编译、viewport 元数据存在。
- 如实现新状态，先为状态/handler 写回归断言，证明成功、失败、取消和重复激活都保持业务语义。
- 样式门禁检查新增动效只在目标组件生效；`prefers-reduced-motion` 下没有非必要动画；不产生横向滚动或降低热区。

### 手动回归矩阵

| 维度 | 至少覆盖 |
|---|---|
| 路由与视口 | P20、P23、P24、P30、P41；320×568、360×480、360×800、390×844、430×932。 |
| 弹层操作 | 按钮打开/关闭、遮罩、Escape/系统返回、连续双击、保存/取消、错误提示、关闭后焦点与滚动恢复。 |
| 键盘 | iOS Safari + WKWebView、Android Chrome + WebView；中文输入/联想、数字输入、键盘“下一项/完成”、字段滚动、底部操作、旋转与收起。 |
| 手势（若获准实现） | 竖向滚动、水平阈值前后、快滑/慢拖、取消、列表边缘、行按钮、横向控件、文本选择、系统返回。 |
| 无障碍 | 减少动态、屏幕阅读器名称/状态、系统放大、粗体文本、键盘焦点可见性与顺序。 |
| 功能 | 比对操作前后原型路由、筛选、角色、业务记录、反馈文案和草稿；确认没有重复写入。 |

测试记录须分开写桌面物理键盘、浏览器模拟 viewport、真机软键盘、真机系统手势。已有浏览器记录确认了不少焦点和弹层行为，但没有证明真实 iOS/Android 软键盘和宿主 WebView inset；相关项目标为“待设备验收”，不是阻断当前规范交付。

## 6. 阶段五验收结论

- **能现在交付**：统一交互状态、毫秒建议值、页面/面板动效边界、下拉/左滑手势行为规则、键盘适配方案、系统差异、实现优先级与回归矩阵。
- **需要后续业务授权与设备**：真正接入网络刷新的下拉刷新、改变现有列表操作方式的左滑、面板拖拽、真实 iOS/Android 软键盘和原生 WebView inset 的实现验收。
- **本阶段保持**：原型业务逻辑、按钮和字段、路由、状态、视觉标记及用户已确认的黑白灰方向。

## 7. 官方依据

- [Apple HIG：Motion](https://developer.apple.com/design/human-interface-guidelines/motion) — 动效服务于反馈并尊重个体偏好。
- [Apple HIG：Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets) — sheet 适合相关的短任务；复杂流程考虑其他呈现，主界面避免同时堆叠多个 sheet。
- [Apple HIG：Virtual Keyboards](https://developer.apple.com/design/human-interface-guidelines/virtual-keyboards) — 根据内容选择合适的系统键盘并保证键盘上方控件可用。
- [Material Design 3：Motion](https://m3.material.io/styles/motion/overview) — 使用可理解、有目的的状态过渡。
- [Android：Partial bottom sheets](https://developer.android.com/develop/ui/compose/components/bottom-sheets-partial) — 部分展开/全屏/关闭属于明确面板状态，拖拽规则需与状态模型一致。
- [Android：Software keyboard & WebView insets](https://developer.android.com/develop/ui/views/layout/sw-keyboard) · [WebView window insets](https://developer.android.com/develop/ui/views/layout/webapps/understand-window-insets) — 键盘与安全区需同宿主一起测量，避免重复应用和清焦循环。
- [W3C：`prefers-reduced-motion`](https://www.w3.org/WAI/WCAG22/Techniques/css/C39.html) — 可用媒体查询减少交互触发的动效。
