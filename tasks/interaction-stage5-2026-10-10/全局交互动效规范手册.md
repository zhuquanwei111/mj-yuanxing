# 全局交互动效规范手册｜阶段五

| 项目 | 内容 |
|---|---|
| 日期 | 2026-10-10 |
| 范围 | 明镜 49 个移动端入口 |
| 状态 | 交互规范完成；后续切片已实现弹层进出动效，不新增手势或改变业务流程 |

## 1. 目标与边界

为手机端建立一套跨 iOS、Android 与移动 WebView 的反馈、转场、手势、弹层和软键盘规则。动效只帮助用户看懂“我点中了什么、页面发生了什么、下一步在哪里”，不做装饰，不代替文字状态。

此前确认的黑白灰视觉、页面信息架构、入口、文案、表单校验、业务状态、权限、路由和处理结果均保持原样。这里标注“规范目标”的内容是后续实现准则，不代表已经加进原型；弹层动效另有后续切片记录。不会以无数据源的假刷新、假加载或假触觉反馈模拟真实业务。

本规范用三种状态标记事实：

| 标记 | 含义 |
|---|---|
| **当前已实现** | 可在 HTML/CSS/JS 或浏览器验收记录中确认。 |
| **规范目标** | 后续实现时应遵循的设计参数，不代表当前已上线。 |
| **需要真机验收** | 桌面浏览器视口不能替代 iOS/Android 软键盘、系统安全区、系统返回等验证。 |

## 2. 全局动效令牌

所有持续时间均为本项目的推荐值；Apple HIG 与 Material 说明动效应有目的、跟随预期并保持克制，但不会为本项目这些控件规定统一毫秒数。先沿用原型已存在的响应速度，再用真实设备验证是否需要调整。

| 场景 | 规范目标 | 缓动与属性 | 当前实现 |
|---|---|---|---|
| 按下按钮/图标 | 120–160ms；触摸开始立即给可见反馈 | `ease-out`；优先背景、描边、亮度或透明度，不缩小点击热区 | **已实现**：按钮反馈约140–160ms；按下改变亮度/透明度，主要操作不靠缩放表达。 |
| 筛选、分段、页签选中 | 140–180ms；切换后立即更新内容 | `ease-out`；只过渡颜色、描边和轻量指示，不延迟数据切换 | **已实现**：现有分段和筛选有约150–160ms样式反馈；Ionic 分段切换后会恢复键盘焦点。 |
| 展开/折叠或轻量提示 | 160–220ms | `ease-in-out`；内容出现时同步更新可访问状态，避免只动画高度 | **部分已有**：页面有原生折叠内容；各页面未统一动画。 |
| 居中对话框 | 面板进入/退出160–220ms；遮罩140–180ms | 进入 `ease-out`，退出 `ease-in`；遮罩透明度与面板轻位移配合 | **已实现**：面板淡入/淡出160ms、纵向位移6px/200ms；遮罩180ms。关闭动画结束后再解除 inert 并恢复触发器焦点。 |
| 底部操作面板 | 进入/退出200–260ms | `cubic-bezier(.2, 0, 0, 1)`；只用 `transform: translateY()` 和遮罩透明度 | **已实现**：面板纵向位移20px/240ms、透明度180ms；保留贴底、安全区与原关闭方式，无拖拽手势。 |
| Toast/轻反馈 | 进入/退出160–200ms；存在约2.5–3.5秒后自动消失 | `ease-out`；文字清楚说明结果，带操作按钮的消息要让操作可达 | **已实现**：约180ms淡入并上移8px，默认3.2秒后清除，容器有 `role="status"`/`aria-live="polite"`。 |
| 页面路由 | 默认不做全屏页面转场；若之后证明有益，限制在160–220ms | 不动画固定导航，不缩放整台手机；前进/返回保持方向与滚动语境 | **未实现页面级动画**：hash 路由渲染，历史返回恢复来源页滚动等上下文。 |
| 长耗时业务 | 由真实请求或既有模拟进度驱动 | 明确显示进行中、完成或失败；不以装饰动画冒充完成 | **当前有局部演示计时**，不得把单页模拟步骤当成全局加载规范。 |

现有弹层过渡值写在共享 overlay 样式中；对话框与底部面板采用分开的距离和时长，避免为了统一而牺牲面板语义。按钮/状态反馈令牌仍是统一样式收敛建议。

动效属性优先使用 `transform` 与 `opacity`。避免对整页 `height/top/left/margin` 做逐帧动画；如内容折叠要改变高度，应保证滚动位置稳定，并在动画结束前就更新可访问状态。新状态不能因为动画结束前后被重复点击或重复提交。

## 3. 按压、状态切换与操作反馈

| 用户动作 | 反馈顺序 | 必须保留的行为 |
|---|---|---|
| 点主/次按钮 | 立即按压态；执行原有事件；成功/失败出现原有结果反馈 | 不改变 `onclick`、表单 `type`、防重复提交逻辑或结果文案。 |
| 选中筛选/分段 | 当前项立即显出选中边界/底色；对应列表或视图更新 | 不只用颜色区分；保留文字/计数、ARIA 选中态、键盘激活和焦点。 |
| 表单校验失败 | 错误靠近字段；需要时聚焦第一个错误字段；用户输入不丢 | 不清空值，不静默关闭表单，不伪造成功。 |
| 保存/采纳/发送成功 | 状态文字或 Toast 明确说明已完成和对象 | 草稿、预览、确认、已发、失败等状态不得合并；不得以按钮变色代替状态结果。 |
| 加载/处理中 | 仅在确有异步操作或原有演示步骤期间出现 | 防止重复触发；等待失败后提供可见恢复方式；没有真实等待时不要加空转骨架或延迟。 |
| 无结果/无权限/不可用 | 保留当前筛选条件，说明范围或限制，并保留已有返回路径 | 不仅留白，不用不可见控件或灰色暗示替代文字。 |
| 可撤销的变更 | 完成后说明结果并给清楚的撤销入口 | 仅在原业务支持撤销或新任务明确增加后使用；不可凭空承诺回滚。 |
| 高影响或不可逆操作 | 说明对象与后果，再使用既有确认步骤 | 不对每个普通操作都加确认，也不移除原有必要确认。 |

焦点是交互反馈的一部分：键盘用户能看到当前落点；组件重绘后，焦点留在对应控件；对话框关闭后回到触发它的控件。禁用态继续使用真实 `disabled`/现有阻断，不只靠低对比色模拟。

## 4. 页面导航与返回

1. 底部主导航只切换已有的顶层入口，保持当前选中项可辨认；页面内操作继续留在页面内容区。
2. 返回按钮、系统返回/浏览器后退、关闭弹层各自遵循现有来源路径。关闭一个弹层应回到其父页面；不能关闭后跳到无关首页。
3. 新进入的列表/详情按现有导航规则开始或保存滚动；返回来源页时，恢复该用户的筛选、页签、展开项和滚动位置。
4. 默认不对整页做淡入淡出，避免掩盖页面更新、干扰滚动恢复、造成表单焦点闪失。未来若引入，先验证前进/返回方向、减少动态偏好、读屏焦点和短屏布局。
5. iOS 边缘返回与 Android 系统返回区域留给系统；应用不得在系统手势边界上放置左滑业务动作或阻断原生返回。

## 5. 弹层与底部操作面板

### 使用边界

- **快速选择或短操作**可使用当前已有的底部面板，例如从短列表选择一个负责人。
- **多字段编辑、长文本、评分、复杂决策**使用受限全屏编辑视图/独立路由；不要把复杂流程压进短面板。
- 同一时刻只呈现一个模态层。不能在一个面板上继续叠第二个面板；转入另一个步骤时，关闭或替换原面板并保留必要上下文。
- 面板从手机内容区域底部出现，宽度不超过屏幕；内容区内部纵向滚动，标题/关闭和主要操作可达，底部留系统安全区。
- 遮罩点击只关闭可安全取消的面板；包含尚未保存编辑时按既有取消/保存规则处理，不能因为动画自动提交或静默保存。
- 保留显式关闭/取消操作、键盘 Escape/系统返回、焦点限制和关闭后焦点恢复。
- 拖拽关闭只有在实现了明确抓手、手势方向和取消回弹规则后才启用；内容区横向滚动与拖拽必须互不抢事件。

**当前已实现**：弹层使用 `role="dialog"`、`aria-modal`、标题/描述关联，背景区域 `inert` 并锁住主内容滚动；Tab 焦点限制在弹层内，Escape/遮罩可关闭。现在对话框与底部面板使用 opening/open/closing/closed 生命周期；退出期间继续保持 inert 与焦点限制，动画结束后恢复触发器焦点。短选项面板贴底、最大高度约82%，底部留 `safe-area-inset-bottom`。复杂编辑框使用内部滚动和黏性操作区。没有拖拽手势；减少动态偏好下动效立即结束。

苹果建议只同时显示一个 sheet，复杂/长流程考虑全屏界面；Android 的 bottom sheet 用于承载次级内容，并可按任务设计部分展开。这里将平台建议映射为本项目的“短操作才用面板，复杂编辑走整页”规则。[Apple HIG：Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets) · [Android：Bottom sheets](https://developer.android.com/develop/ui/compose/components/bottom-sheets-partial)

## 6. 手势规则

**默认手势是系统原生点击和纵向滚动。** 原型目前没有自定义 `touchstart`/`pointermove` 识别器，也没有下拉刷新或左滑列表动作；横排分段明确关闭 Ionic swipe-gesture。未来添加手势前必须先有真实业务需求、可见替代操作和独立验收。

| 手势 | 允许范围 | 触发与状态 | 键盘/无障碍替代 | 当前状态 |
|---|---|---|---|---|
| 纵向滚动 | 页面主内容区，或聊天/面板自己的内容区 | 用浏览器原生滚动和回弹；不要在子容器滚到底时把手势吞掉 | 滚动容器保持可聚焦且有可读标题 | **已实现**；若干内部滚动区设置了 `overscroll-behavior: contain`。 |
| 下拉刷新 | 未来仅限确有服务端更新能力的列表，且必须位于列表顶部 | 起点 `scrollTop===0`；向下位移建议至少56 CSS px才进入“释放刷新”；显示“松开更新/正在更新/已更新/更新失败”。刷新只发起一次，失败可重试；筛选和滚动语境保留 | 提供固定可见的“刷新”入口或重试按钮；读屏宣布状态 | **未实现**；静态样例数据没有刷新目标，不在本阶段伪造。 |
| 左滑揭示行操作 | 未来仅限有明确行级动作、且页面空间确实不足时 | 水平位移至少56 CSS px且水平运动明显大于纵向运动；释放后只揭示操作，不直接删除/确认；同一列表最多展开一行；点外部、滚动或导航时关闭 | 行内保留可见按钮/更多菜单作为同功能入口；Tab 可访问所有操作 | **未实现**；现有行操作可见，不增加滑动依赖。 |
| 面板拖拽 | 未来只在面板有可见抓手且用户可预测状态时 | 仅抓手区域开始手势；向上扩展、向下关闭；未达阈值回弹到原状态；设定位移/速度阈值并避免与内容滚动抢事件 | 始终显示关闭按钮；键盘 Escape/系统返回可以关闭 | **未实现**；现在通过关闭按钮、Escape/遮罩关闭。 |
| 横向页内导航 | 仅适用于确属连续内容的轮播/时间序列，不用于主导航 | 仅在项目清单明确时启用；页面滚动优先于横向手势 | 提供有名称的前后按钮与位置文本 | 当前分段采用点击/键盘，不以滑动作为切换方式。 |

不能仅凭 `touch-action:none` 或 `preventDefault()` 锁住整个页面。手势判定应让垂直滚动优先；不在系统边缘手势区放置水平删除动作；设备触觉反馈只有在原生容器提供、用户设备支持且动作语义明确时才考虑，不使用网页振动 API 来假装 iOS/Android 触觉。

## 7. 软键盘与表单适配

### 规则

1. 输入框声明正确的 `type`、`inputmode`、`autocomplete`；数字/金额/手机号调用合适键盘，不用自绘键盘替代系统输入。
2. 焦点进入字段后，字段标签、输入内容、错误提示、关闭按钮和保存/取消都必须留在可见视口；长表单滚动字段区，操作区保持可达。
3. 键盘出现/收起按可见视口变化适配，不按固定设备高度推断。优先响应浏览器/WebView的 viewport 与安全区；如果监听 `visualViewport`， resize 回调不能清除输入焦点或反复重绘整个表单。
4. iOS Safari 与 Android Chrome/WebView 的软键盘上推、视口缩放和底部安全区存在差异。一次只由 WebView 容器或网页负责某个 inset，避免双重添加安全区/键盘高度。
5. 输入错误后保留值，滚动并聚焦首个错误字段；关闭面板后还原触发器与来源滚动。多步表单的 Enter/下一步、换行、IME composing 必须按控件类型处理。
6. 键盘遮住底部 Tab 栏时，不允许底栏与固定保存区同时争抢视口；编辑流程应优先保持当前字段和编辑操作可见，并在键盘收起后还原原布局。

### 当前实现与验证边界

**当前已实现**：移动视口元数据、`100dvh` 手机容器、底部 `env(safe-area-inset-bottom)`，表单弹层内部滚动和黏性操作区；打开弹层时聚焦首个输入/可操作项，Tab 焦点限制、Escape 关闭及关闭后焦点恢复；P10、P20、P23、P24、P30、P41 等有键盘和焦点回归记录。

**未实现/未证明**：原型没有针对 `visualViewport` 的键盘监听；真实 iOS/Android 软键盘、不同系统键盘高度和原生 WebView inset 未完成真机验收。浏览器物理键盘通过不能被写成软键盘通过。

Android WebView 会随 IME 改变 visual viewport，开发时要避免 resize 清焦导致键盘关闭循环，并防止网页和原生容器重复施加 inset；具体依据见 [Android WebView window insets](https://developer.android.com/develop/ui/views/layout/webapps/understand-window-insets) 与 [Android software keyboard](https://developer.android.com/develop/ui/views/layout/sw-keyboard)。

## 8. 减少动态、键盘和辅助技术

- 保留 `prefers-reduced-motion: reduce`：所有非必要转场、位移和滚动平滑关闭，状态仍通过静态文字/轮廓可辨。
- 所有操作有可见 `:focus-visible`；不把 hover 当作唯一反馈；图标按钮保留可访问名称。
- 单选/分段保留 `aria-selected` 或 `aria-pressed` 与可见选中态同步；弹层提供标题/描述语义。
- Toast/进度/校验采用已有 `aria-live` 或可聚焦错误提示；不只靠闪动、颜色、声音或震动提示。
- 不把键盘快捷键分配给系统常用按键；不覆盖 iOS/Android 系统返回、放大或辅助触控手势。
- 文字放大与系统字体变化后，按钮/卡片可以增长并滚动；不固定高度裁掉文字。

Apple HIG 强调动效应有目的并可选；W3C 建议用 `prefers-reduced-motion` 响应减少动态偏好。[Apple HIG：Motion](https://developer.apple.com/design/human-interface-guidelines/motion) · [W3C C39](https://www.w3.org/WAI/WCAG22/Techniques/css/C39.html)

## 9. 阶段五交互验收清单

| 验收项 | 通过标准 |
|---|---|
| 行为保护 | 既有按钮文本、路由、筛选条件、业务状态和处理结果不因动效变化；所有状态可在动效关闭时识别。 |
| 响应 | 轻反馈不阻塞点击；无重复请求/重复状态写入；动画完成前后焦点与页面上下文连续。 |
| 弹层 | 320×568、360×480、360×800、390×844、430×932 检查；关闭、Escape/系统返回、遮罩、焦点循环、焦点恢复、内容滚动和安全区通过。 |
| 键盘 | 桌面物理键盘检查 Tab/Shift+Tab/Enter/Escape；真机测试 iOS Safari 与 Android Chrome/WebView 的字段可见、滚动、软键盘收起和固定操作区。 |
| 手势 | 只有批准的列表实现下拉/左滑；上限、取消、误判、纵向滚动、无障碍替代与系统边缘返回均通过；未实现手势不列为已验收。 |
| 动态偏好 | 开关减少动态后，所有状态和操作仍可理解、可执行；没有残留的位移/循环动画。 |
| 记录 | 记录设备/系统/浏览器、CSS视口、路线、关键操作、最终状态、控制台、截图及失败项。 |
