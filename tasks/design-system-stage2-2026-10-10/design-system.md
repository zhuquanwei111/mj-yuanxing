# 明镜移动端设计系统｜阶段二

日期：2026-10-10  
阶段：阶段二「统一移动端设计系统搭建」  
状态：规范与按钮样例已交付；已按用户指示进入阶段三标杆页试装

## 1. 设计依据与边界

保留参考图中柔和明亮的轻插画卡片布局与清晰信息层级；按用户最新反馈，当前全局配色统一为黑、白、灰。参考图01/09、03/04、05/06继续用于卡片布局、留白和内容组织，不复制其彩色强调；暗色参考08与倾斜拼贴参考02也不作为全局页面基线。具体案例与采纳边界见[阶段一调研报告](../design-research-stage1-2026-10-10/report.md)。

原型里约49个可访问路由和所有入口都以手机完整体验为目标。源码盘点到368处 `<button>` 标签写法（含模板中的重复渲染代码），其中278处使用 `.btn` 类；按钮、页签、筛选、底部导航、图标操作等样式分散在多段 CSS 覆盖中。这些数字是源码出现次数，不代表单屏同时显示的控件数。

**用户新增的全局约束：现有全部按钮外观都要重做，交互与功能必须完整保留。** 本规范因此覆盖按钮、图标按钮、文字操作、筛选项、分段选择、页签、底部导航等所有由 `<button>` 承载的控件。更新视觉规则，不把原生按钮批量迁移成另一套组件；原有 `type`、文案、DOM 次序、点击/提交处理器、路由、权限判断、选中/禁用状态和业务结果均为保护项。

本文件的黑白灰视觉方向替代旧的[手机工作台设计基线 V2](../design-baseline-mobile-v2.md)中按钮与配色决策。旧文件中的移动端可用性、业务信息和触控尺寸检查仍可作为质量参考；本阶段不修改原型源码，样例也独立于业务原型。

## 2. 全局视觉原则

| 维度 | 统一规则 |
|---|---|
| 气质 | 明亮、克制、有秩序；插画与装饰按页面信息密度克制使用，黑白灰建立层次。 |
| 阅读 | 手机纵向优先；标题、业务对象、状态、主操作顺序清楚，长中文可换行。 |
| 色彩 | 黑、白、灰为唯一界面色系；主操作黑底白字，次级选择使用浅灰底，危险与业务状态通过文案、图标、边界和形状共同识别。 |
| 形状 | 按钮圆润但不全做胶囊；按钮、选择控件、内容卡和底部面板用不同圆角层级。 |
| 层级 | 先用排版、间距、浅色分区建立主次；阴影只用于浮层或需要离面的内容。 |
| 业务保护 | 不删改业务字段、信息架构、权限和流程；视觉相似度不作为照搬参考图业务内容的理由。 |

| `neutral-100` | `#F2F2F2` | 次级内容分组、轻状态衬底 |

## 4. 字体、排版、间距与容器

| 令牌 | 规格 | 用途 |
|---|---|---|
| `caption` | 12px / 500 / 行高 1.45 | 次级时间、辅助标注；关键提示不得只用此级 |
| `body-sm` | 13px / 400–500 / 行高 1.5 | 紧凑元数据 |
| `body` | 14px / 400–500 / 行高 1.55 | 列表、表单、说明正文 |
| `body-lg` | 16px / 400–500 / 行高 1.5 | 重要正文、输入内容 |
| `title-sm` | 18px / 600 / 行高 1.3 | 区块标题 |
| `title` | 22px / 650 / 行高 1.25 | 页面标题 |
| `display` | 28px / 700 / 行高 1.15 | 入口主标题或关键业务数字，按需使用 |

字体采用系统字形：`-apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang SC", "Noto Sans CJK SC", "Microsoft YaHei", sans-serif`。不加载外部字体；数字对齐需要稳定时使用等宽数字。常规页面正文不低于14px，辅助文字保留至少12px并使用足够对比度。

基础间距单位为4px，主节奏为 `4 / 8 / 12 / 16 / 24 / 32`。页面左右安全留白在窄屏至少16px，常规屏幕20px；内容宽度随设备变化，原型画布目标覆盖320–430 CSS px，并处理顶部与底部安全区。业务内容不得因按钮加宽或变高造成横向溢出。

| 元素 | 圆角 | 深度 |
|---|---:|---|
| 普通按钮 | 14px | 默认无阴影 |
| 主操作按钮 | 16px | 仅在需要和背景分离时用轻阴影 |
| 筛选/分段胶囊 | 999px | 以填充色表达选中，不加投影 |
| 内容卡片 | 18px | 白底；用间距和浅色分组区分层级 |
| 底部动作面板 | 24px（上缘） | 单层柔和投影，配遮罩和拖拽手柄仅限原型现有手势 |

## 5. 按钮与操作控件系统

### 5.1 全量覆盖范围

下列控件都属于本轮视觉替换：`.btn` 主/次/弱化/危险按钮、`mback` 返回、关闭/加号/更多/发送图标按钮、`.ttab` / `.ptab` / `.mtabs button` 页面视图和底部导航、`.fchip` 筛选、`.p70-tab` 账期视图、由 `<button>` 实现的列表行和平台/组织操作。原生控件、Ionic 分段按钮与模板生成按钮都遵循同一色彩和状态层级；各类控件的语义和空间形态依用途保留。

### 5.2 视觉变体

| 变体 | 视觉规则 | 何时使用 |
|---|---|---|
| 主操作（Primary） | `accent-600` 黑色实底、白色 600 字重、16px 圆角；按下转 `accent-700` | 当前页面最重要、已有的推进操作；每个操作区最多一个主按钮 |
| 次操作（Secondary） | 白底、`line-control` 细边、`ink-900` 文字；按下切到 `accent-100` | 与主操作并列的查看、取消或返回等既有动作 |
| 柔和强调（Tonal） | `accent-100` 浅灰底、深色文字，无重阴影 | 非主操作但需突出；保留已有 `.btn.g`、搜索/查看类操作的语义分层 |
| 文字操作（Text） | 无填充、无边框，文字以 `accent-700` 或正文色呈现；触控区通过内边距扩展 | 卡片内轻量链接、更多、次级入口 |
| 危险操作（Destructive） | 白底黑色描边与 `danger` 文字；最终危险操作可用黑底白字 | 原型中已有的停用/删除/解除等危险动作；不新增确认步骤或改变操作结果 |
| 图标按钮（Icon） | 图标约20–22px，独立视觉容器；默认白/透明底，按下有可见的浅灰底反馈 | 返回、关闭、添加、更多、发送等仅图标操作；必须保留已有可访问名称 |
| 选择控件（Choice） | 未选中为浅底/清晰描边，选中为 `accent-100` 浅灰底+深色字/边；可同时保留当前选中符号 | 筛选、视图切换、分段项、分类选择；优先用浅灰选中态；对日期等单值选择可用黑底白字 |
| 底部导航（Navigation） | 默认弱化图标和文字；选中项以黑色文字/图标与浅灰底标识区分 | 现有底部主导航；保留原有位置、入口和选中状态机制 |

### 5.3 尺寸与触控

- 跨 iOS/Android 共用原型按48 CSS px作为可触区域下限；主要提交按钮建议52–56px高，普通操作和图标按钮至少48×48px。
- 视觉图标可以小于触控区域，热区通过控件本身或周围透明内边距保证；相邻独立操作留出至少8px，避免误触。
- 页面内横排操作允许按现有容器换行；长文案可折行、按钮宽度可伸展，不得压缩为小字或出现横向滚动。
- 底部导航和固定操作区避开 Home Indicator 与系统手势区；安全区留白不计入可见按钮高度。

此基线满足 Android 至少48dp触控目标，并高于 Apple iOS/iPadOS 44pt 常规目标。平台单位随设备密度变化，真实实现仍需在原型浏览器与目标设备检查热区。

### 5.4 状态与反馈

| 状态 | 外观规则 | 行为边界 |
|---|---|---|
| 默认 | 按上述变体区分主次 | 保留现有事件和触发方式 |
| 按下 | 背景/描边/文字有即时变化，可轻微压暗；不通过大幅缩放改变热区 | 视觉反馈，不节流、不延迟已有处理器 |
| 键盘焦点 | 至少2px `focus` 外环及2px间隔，保持文字可读 | 保留原生 Tab/方向键行为、焦点归属与顺序 |
| 选中 | 通过浅灰填充、深色文字/图标、当前已有指示符组合 | 不改变原状态字段、ARIA状态或业务筛选逻辑 |
| 禁用 | 中性低对比底色、正文色仍能辨认；光标与按下态不暗示可用 | 保留原 `disabled` 与触发拦截，不通过 CSS 伪造禁用 |
| 处理中/成功/失败 | 仅按原型已存在的状态展示文字、图标或状态色反馈 | 不新增请求、延时、toast、确认或状态迁移 |
| 减少动态 | 动效关闭或缩短；焦点和状态仍有静态可见差异 | 尊重 `prefers-reduced-motion` |

交互响应动效建议120–180ms，缓动克制；禁止自动循环、持续脉冲或仅靠动画表达结果。焦点样式适用于鼠标/键盘辅助操作，移动端按压反馈同样清晰。

### 5.5 按钮换肤的行为保护清单

实现阶段仅调整 CSS 令牌、外观、必要的可触高度和视觉状态。以下项目逐批冻结并回归：

1. 不增删按钮，不改按钮标签、文字、图标含义、排序、所属容器或页面路由。
2. 不改 `onclick`、事件委托、表单 `type`、提交/取消规则、权限守卫、确认步骤、数据写入和提示结果。
3. 不改 `.on` 等业务选中类由谁设置，也不把按钮改成 `<a>`、`div` 或未经验证的第三方按钮组件。
4. 图标按钮保留 `aria-label`/可见标签；页签和选择器保留现有键盘可达性及选中态同步。
5. 每批完成后，以原始动作清单对照同一组入口：点击前后页面/状态/路由/反馈一致，只接受样式差异和触控尺寸改善。

## 6. 组件库与适配范围

| 组件族 | 统一要点 | 适配/验收方向 |
|---|---|---|
| 按钮与选择控件 | 本文第5章；跨页面同一语义保持同一变体 | 点击、键盘、禁用和选中态逐种回归 |
| 导航与页签 | 当前选中状态清晰且始终可见；长中文可换行 | 320px窄屏不横溢；底部安全区完整 |
| 表单控件 | 白色输入面、清晰边界、标签与错误说明相邻 | 保留既有验证/错误逻辑；移动端输入字号至少16px |
| 卡片与列表 | 白色或浅色分组；标题、对象、状态、动作层次分明 | 高密度页保持一列可扫读，不强迫缩小触控目标 |
| 弹窗/底部面板 | 延续现有尺寸和焦点处理，使用轻背景和清晰动作区 | 不替换现有弹层机制；关闭、Esc、返回焦点按原样工作 |
| 状态标签/反馈 | 黑、白、灰按层级使用；状态配文案、图标或边界 | 不用装饰色代替风险、完成、错误等业务语义 |

本项目继续采用现有单文件原型和原生 DOM 事件；已有 Ionic Core 分段控件只纳入统一视觉主题，不把 Ionic 默认视觉扩散为全局模板。组件清单按原型真实出现控件归档，遇到业务特有控件时继承同语义变体，不另造无依据的平行样式。

### 风险与处理

| 风险 | 处理方式 |
|---|---|
| 各页 CSS 后置覆盖造成按钮颜色/尺寸不一致 | 阶段3/4先归并全局按钮令牌，逐个清理冲突选择器，并按状态和路由截图检查。 |
| 统一按钮高度后某些紧凑区块挤压/换行 | 保持原容器和排版意图，允许按钮组换行或伸展；禁止缩小点击热区来迁就布局。 |
| `button` 同时承担导航、筛选、分段等语义 | 按功能映射视觉角色，保留事件、语义/ARIA、选中状态和既有键盘支持。 |
| 亮色浅底导致文字/边界不清 | 使用本文的深色文字与交互边界令牌；避免浅灰文字或边界单独承载关键状态。 |
| 视觉修改被误认为允许重排或删减业务 | 每批维护按钮原样清单，验收以业务动作前后状态一致为门槛。 |

## 8. 阶段3启动条件与执行切片

阶段二验收后进入阶段3。先选10个标杆页中的3–4个具有代表性的页面完成按钮视觉试装：P20工作台、P21列表/筛选、P10表单、P50排期或P61编辑。其余标杆页覆盖组件差异后再扩展。每个切片包括：

1. 记录页面现有按钮/操作清单、文案、事件、权限、选中/禁用状态与结果。
2. 套用本文视觉角色，先实现共享样式，再处理页面布局例外。
3. 在320、360、390、430 CSS px检查布局、触控和安全区。
4. 回归每个按钮路径并与改动前行为核对；已有交互测试必须通过。
5. 由用户确认标杆页样式后，阶段4按页面类别批量覆盖剩余路由。

本文件不代表已经修改生产原型，也不预先替用户决定每个页面的最终按钮映射。具体页面的样式应用从阶段3的标杆页切片开始。

## 9. 官方可用性依据

- [Apple HIG：Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons)：自定义按钮需要明确按压态，iOS常规触控热区至少44×44pt。
- [Android Developers：Mobile accessibility](https://developer.android.com/design/ui/mobile/guides/foundations/accessibility?hl=en)：移动交互目标至少48×48dp。
- [WCAG 2.2：Target Size (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)：网页交互目标尺寸与间距的最低要求。
- [WCAG 2.2：Non-text Contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)：图形控件边界与状态指示的非文本对比要求。
