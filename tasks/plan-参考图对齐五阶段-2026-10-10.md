### 0.4 本轮计划必须解决的核心矛盾

用户本轮重申"所有后续设计工作必须基于我提供的参考图调性"，而当前实现是在"排除参考图彩色强调、纯黑白灰"的前提下完成的。**这两者的关系必须先在阶段一锁死**，否则阶段四、阶段五的既有成果是否有效无法判定。这是本计划唯一的真正阻塞项。

## 1 · 项目整体概述

### 1.1 项目目标

在**不改动业务逻辑、功能模块、信息架构与核心流程**的前提下，把 49 个移动端入口的视觉样式、布局细节与交互体验提升到参考图所代表的调性水准与 Dribbble 优质移动端设计质量，并保证前端可还原、可落地。

交付判据（三层，缺一不算完成）：

1. **视觉**：与参考图调性一致，全站风格 100% 统一，无遗留彩色强调与样式冲突；
2. **可用**：移动端触控可用性达标（命中区、无横向溢出、窄屏可读、状态可辨），覆盖 iOS HIG 与 Android 基础习惯；
3. **可落地**：单文件 Vanilla 实现约束内的动效与交互规范明确，前端可按规范还原。

### 1.2 范围

**纳入**：`明镜产品原型.html` 的手机端产品体验、原型评审预览支持、设计系统文档、交互规范文档。

**排除**：桌面产品、后端 / AI 能力层、业务规则与数据口径、真实服务接入、生产发布。

**保护项（红线）**：页面模板、JavaScript、事件处理器、路由与 hash 语义、表单类型、权限判断、选中/禁用状态、业务文案与业务结果。所有阶段均以源码指纹（当前 `efd2aa8c...b3bdc9`）校验保护项未被改动。

### 1.3 核心原则

1. **参考图调性唯一锚点**：所有阶段以阶段一锁定的调性文件为准，不自行发散。
2. **风格统一优先于单页出彩**：先做标杆模板，再批量复制覆盖；不允许"只有一个板块出彩"。
3. **增量纵向切片**：每次改一个可独立查看的完整路径，改完立刻自评。
4. **结构先于视觉**：信息顺序、主次、对象与状态先行；不以加间距、调字号冒充改版。
5. **既有成果不推倒**：阶段一至五已交付物为基线，本轮为**对齐与收口**，不是从零重做。
6. **无证据不改**：路由、组件、样式只在有证据时改动，保留旧 hash 映射。

### 阶段 2 · 统一移动端设计系统搭建

| 项 | 内容 |
|---|---|
| **核心目标** | 把调性裁定落成单一令牌源，消除 8 段 `:root` 覆盖并存的结构债，作为 49 页唯一标准 |
| **前置依赖** | 阶段一调性裁定通过 |
| **工作量占比** | 原始 15% ｜ 本轮剩余 20%（因涉及令牌源收敛） |

**任务清单**

1. **色彩体系**：按裁定结果给出主色/辅助色/中性色/功能色完整色阶与使用规则；功能色必须**同时由文案、图标、边框或形状共同表达**，不允许只靠颜色深浅传达状态。
2. **令牌源收敛**：将 8 段 `:root` 与阶段三/四覆盖层合并为**单一令牌源**，消除同名令牌互相覆盖。
3. **字体系统**：手机全场景字号阶梯、字重、行高；中文换行规则；关键提示不得只用最小档字号。
4. **栅格与间距**：4px 基础栅格（组内 / 区块间分档）、安全区域、窄屏内距收紧规则。
5. **触控规范**：可交互元素最小尺寸（沿用当前 48px 基线，窄屏不低于 43px）、热区、按压/禁用/焦点反馈规则。
6. **核心组件库**：全量移动端组件的样式、状态、交互规则——导航、按钮、输入框、卡片、弹窗、开关、分段控件、列表行、标签、空态。
7. **按钮专项**：按既有全局约束完成全部由 `<button>` 承载的控件（源码含 368 处写法、278 处 `.btn`）外观重做，**交互与功能完整保留**。
8. **状态完备性**：每个组件与页面明确 空 / 加载 / 部分加载 / 错误 / 成功 / 无权限 / 禁用 七态的表现规范。

**交付物明细**

- `阶段二/设计系统规范.md`（更新既有 `design-system.md`）
- `阶段二/令牌源收敛说明.md`（旧 → 新令牌映射，含兼容策略）
- `阶段二/组件库清单.md`（组件 × 状态 × 交互规则）
- `阶段二/组件样例页.html`（独立于业务原型，可单独打开）

**验收标准**

- 令牌源唯一，源码中不再存在互相覆盖的 `:root` 主题块；
- 组件清单覆盖全部既有控件，且每个组件都有状态定义；
- 对比度达标（正文 ≥4.5:1，交互轮廓 ≥3:1），并记录实测值；
- 组件样例页可在 320/360/390/430 视口正确显示；
- 阶段一调性关键词在色板、字体、间距、组件中均有可追溯的对应。

**风险提示**

- 令牌源收敛会一次性触碰全站样式，**回归面最大**；须先冻结基线截图，收敛后逐角色抽查。

- 收敛过程中易出现"顺手改文案"，触碰保护项；每次提交跑指纹校验。

- 全站无遗留彩色强调与未收敛的旧令牌（可按裁定结果写成自动断言）；
- 旧深链不落空，唯一 hash 映射完整；
- 无新增控制台 error / warn；
- 组件复用率达预期，例外清单每条都有理由。

**风险提示**

- 全量覆盖依赖共享样式层，**单点改动影响 49 页**；须按页面族分批改、每批即时自评。
- "只见样式不见结构"是上一轮通病：只改 CSS 而主次仍混乱会导致界面依然像堆叠卡片；每页先定核心任务、对象、主操作、次级入口，再实现布局。
- 窄屏（320px）与短屏是问题最集中处，须实测而非推算。
- 批量替换易误伤已有交互：筛选、视图切换、返回状态、表单校验需逐项回归。

### 3.2 优先级排序

**P0 · 旗舰标杆（10 页，必须先完成并验收）**
P00、P20、P21、P22、P10、MY、P42、P15、P50、P61
—— 覆盖全部 8 种页面类型，是模板来源。未验收不得进入 P1。

**P1 · 核心业务闭环（高频角色路径，14 页）**
- 运营主线：P23、P24、P25
- 经营管理：P13、P14、P16、P93、P94、P95
- 经纪与培训：P30、P30D、P31、P32、P40
—— 决定"每天真在用的人"的体验，风险与价值都最高。

**P2 · 支撑工作区（11 页）**
P33、P41、P41D、P51、P52、P60、P62、P70、P71、P82、P83
—— 单角色深度任务，复用 P0/P1 模板度高。

**P3 · 入口与协议层（8 页）**
P01、P02、P03、P11、P12、P96、P90、P91
—— 低频但影响信任感（入驻、权限、平台侧）。

**P4 · 主播自助与消息（6 页 + AI）**
P80、P81、P84、P85、P92、AI
—— 主播端为独立触达面，需单独确认手机场景（碎片时间、单手操作）。

**P5 · 异常与边界（贯穿全站）**
空态、错误态、无权限态、极端数据（最长姓名 / 最大金额 / 0 条 / 10000 条）
—— 不单独成页，但**必须在每个 P0/P1 页面点名覆盖**，是本项目历史漏项最集中处。

### 3.3 排序依据

1. **模板产出价值**：能产出可复用模板的页面优先（P0）。
2. **使用频次**：角色每日必用路径优先（P1）。
3. **风险暴露度**：承载风险、金额、审批语义的页面优先（P15、P42、P70、P71 提前）。
4. **返工成本**：被其他页面复用的样式，越早定型越省（P0 模板 = 全站成本杠杆）。
5. **触达独立性**：主播端与公会端交互模型不同（碎片时间 vs 连续办公），需独立确认。

## 4 · 切片执行操作指引

### 4.1 分步执行方式

本计划按阶段切片，**上一阶段验收通过后再启动下一阶段**，每阶段独立可交付、独立可验收。

每个切片的最小执行单元是**一条可独立查看的完整路径**，而非一个页面或一段样式。一个切片完成即应满足：可在浏览器打开、可点击走通、无控制台错误、有对应截图或实看记录。

### 4.2 各阶段启动条件

| 阶段 | 启动条件 | 需用户提供 |
|---|---|---|
| 阶段一 | 本计划确认 | 参考图（已提供）＋ **2.1 待决项裁定**（必须） |
| 阶段二 | 阶段一调性裁定与方向说明书书面确认 | 确认指令 |
| 阶段三 | 阶段二设计系统确认通过 | 确认指令 ＋ 视觉验收配合 |
| 阶段四 | **阶段三标杆页用户视觉验收通过** | 确认指令 |
| 阶段五 | 阶段四全量覆盖与视觉验收通过 | 确认指令 ＋ 真机验收条件 |

### 4.3 执行纪律

- **单一 HTML 是高变更风险区**：小步修改，每个增量保持可运行；共享样式不并行编辑。
- **每轮开始前写两行字**：上一轮结论是什么、这一轮要回答什么新问题。不按日历升级保真度。
- **版本冻结并命名**：拿去评审的版本必须冻结（例：`v4 · 2026-10-10 · 用于视觉验收`），因为原型会被反复引用。
- **验收时观察行为，不问意见**：记录"任务成没成、卡在哪、犹豫了多久"，而不是"你觉得好看吗"。
- **保护项每次改动后校验**：源码指纹核对，确认页面模板、JavaScript、事件、路由、业务文案未变。
- **截图与实看记录必须标注路由与视口**；基础脚本通过不代表视觉或点击通过。

### 4.4 每阶段收尾必答

1. 本次改动导致我们砍掉或大改了什么？（答案为"没有"说明这轮是装饰品）
2. 覆盖清单有没有空白项？
3. 旧深链是否仍可达？
4. 保护项指纹是否未变？
5. 结论与下一步决策是否写下来了？

## 5 · 质量保障标准

### 5.1 视觉一致性

| 检查项 | 标准 | 方法 |
|---|---|---|
| 令牌唯一性 | 无互相覆盖的 `:root`；无未声明变量 | 源码断言 |
| 彩色残留 | 按裁定结果：全站无非语义彩色 | 自动断言 + 灰度截图人工复核 |
| 字号合规 | 全部字号属于阶梯档位，无超出档 | 源码扫描 |
| 间距合规 | 全部间距属于 4px 档位 | 源码扫描 |
| 对齐 | 无"孤儿"偏移 | 叠加对齐参考线抽查 |
| 层次 | 模糊截图后仍能分清主次 | 高斯模糊截图 + 5 秒测试 |

### 5.2 移动端可用性

| 检查项 | 标准 |
|---|---|
| 触控命中 | 可交互元素 ≥48px 高，窄屏不低于 43px，热区不小于视觉尺寸 |
| 视口 | 320 / 360 / 390 / 430 CSS px ＋ 360×480 短屏全部无横向溢出与裁切 |
| 状态可辨 | 不只靠颜色传达状态，必须配文案、图标、边框或形状 |
| 对比度 | 正文 ≥4.5:1，交互轮廓 ≥3:1，大字号 ≥3:1（记录实测值） |
| 中文排版 | 长中文可换行，长姓名 / 大金额 / 长备注不破版 |
| 无障碍 | 键盘可达、焦点可见、减少动态偏好正确降级 |
| 导航 | 层级可预测，返回恢复上下文；旧 hash 深链不落空 |

### 5.3 逻辑与业务完整性（保护项）

| 检查项 | 标准 |
|---|---|
| 源码指纹 | 保护项哈希不变，或变动项有明确记录与理由 |

| 控制台 | 无新增 error / warn |
| 数据口径 | 未被样式改动影响 |

### 5.4 交付物质量

| 检查项 | 标准 |
|---|---|
| 结论性 | 每份文档含假设、方法、观察、证据、结论、下一步决策 |
| 可执行 | 规范含具体数值，前端可直接照做 |
