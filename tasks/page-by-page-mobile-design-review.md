# 明镜手机原型逐页视觉与交互设计复核

日期：2026-10-09  
用途：为 [手机信息架构改版规格 V2](spec-mobile-information-architecture-v2.md) 补充逐页的现状、建议布局、采纳参考与验收重点，供后续执行 Agent 按页实施。  
范围：手机产品界面；桌面产品布局与非界面问题暂缓。

## 证据边界与可信度

- 本次规划复核覆盖 `page-coverage.md` 中的 49 个入口：45 个 P 页面、P30D、P41D、AI、MY。每行链接至已有的 360px 页面截图；截图来自此前的本机 HTTP 浏览器验收档案，不是本轮新拍。
- 我重新查看了 49 张首屏证据的总览，并放大复核了运营首页 P20、主播列表 P21、主播详情 P22、培训 P40/P41、组务 P94；同时用 HTML 页面模板和既有审查记录交叉检查页面职责。每张图代表一个状态，不等于该页全部内容/状态都已在本轮重新点击。
- 这些 `qa-*-360.jpg` 是历史基线，有截图早于近期更改；例如 [P30 基线图](browser-evidence/qa-P30-360.jpg)仍包含后来已迁至评审侧栏的两句说明，因此该图不能证明当前手机 UI 仍显示这些文字。实施时应以当前 HTML 和现有 T9 浏览器记录为准，必要时重新截图。
- 因此以下是**基于既有截图 + 源码的逐页设计复核稿**。布局与信息层级建议可供评审；交互细节仍须按各任务的现有入口和状态在执行时逐条确认。不能把截图存在、源代码可见或过去某次页面检查直接算成新版通过。
- 截图上方的“验收尺寸/原型页面”选择器是评审工具，不是手机产品 UI。已有点击路径和弹窗验收记录继续以[覆盖清单](page-coverage.md)、[视觉交互审查](visual-interaction-audit.md)和[浏览器记录](browser-validation.md)为准。

## 全局模式问题清单：不能只修代表页

以下是逐页实施时必须回扫的横切问题；行内建议不是删除信息的授权。

| 模式 | 目标做法 | 全量核对范围 |
|---|---|---|
| 页面说明与小字 | 页头目标/适用角色/价值、AI/人工分工、制作说明放评审侧栏；用户实际要判断的状态、时间、单位、风险和结果保持在产品页并提升层次。 | 页面头、`ailine`、内联小字号、状态标签、表单帮助、弹窗提示、空状态。 |
| 折叠内容 | 主要业务区、名单、排行、历史入口不以 `<details>` 作为唯一入口；改同级视图或具名页面。短帮助才允许折叠。 | 每页所有 `<details>` / `<summary>`，以及页面首次进入时是否可发现关键内容。 |
| 横向溢出 | 业务字段和操作全部重排/换行；没有用户侧横向拖动。周历/数据表等特殊视图需替换为移动列表，不裁字段。 | 全部 `<table>`、`overflow-x:auto`、nowrap、横向 chips/tabs、长按钮和长姓名。 |
| 操作密度 | 每区一个主动作，次操作最多一个；按钮热区统一，更多操作有标签和对象上下文。 | 按钮类名/内联尺寸、图标按钮、底部固定栏、同一行多个动作。 |
| 导航层级 | 主流程短且对象连续；每次打开详情能说清“从哪来、看哪个对象、如何回去”；状态标签不用当作导航。 | 所有 `go()`、返回按钮、名单/筛选/页签/滚动保存、路由直接打开。 |
