## 设计决策

1. **层级先于装饰。** 白色页面和内容表面为默认；用字号、字重、间距、对齐、细分隔线建立层次。页面背景不铺大面积灰色，卡片不加无语义阴影。
2. **按内容选择容器。** 仅把当前首要任务、完整对象信息或需要共同阅读的一组指标放进容器。普通待办、名单、消息和记录采用行列表，不给每一条都套卡片。
3. **区分操作语义。** 每个操作上下文明确一个主动作；提交/确认使用主按钮，次要动作使用轻边框按钮，查看/导航/列表辅助动作保留合适的文字/图标形式。页面确有两个并行核心任务时可例外。定义默认、聚焦、按压、禁用、桌面 hover 状态；手机不依赖 hover。不得因曾反感按钮而全站禁用按钮，也不得把文字操作统一改成实心按钮。
4. **同一业务保留不同信息深度。** P20 是当天可执行队列；P21 是主播状态名单；P93 是跨组风险摘要/分派；P22 是单主播完整依据与协作记录。概览和名单可以链接到同一条任务，但不重复铺开同一段完整任务说明。风险状态统一用文字加圆点/图标，不使用左侧彩色竖条。
5. **保持既有角色与对象可识别。** P00 身份条不分类；P21 名单头像优先复用本地素材，否则使用带浅灰边框的姓名首字占位；名单和详情头像使用一致的 32/64px 规格。
6. **筛选与滚动不丢信息。** 标签名称与数量同行；可横向滚动的筛选保持完整文本，不截断业务类别。全原型所有页面和内部区域均不显示滚动条；隐藏仅改变外观，不禁用滚动。
7. **状态只呈现真实可达项。** 空结果、错误、成功、禁用和加载反馈对应现有逻辑；没有耗时操作则不造加载动画；不增加示例对话或业务数据。
8. **单文件小步改动。** CSS 先建立令牌，再整理基础、共用组件、页面样式；不重写整份 HTML，不删除可能仍在使用的旧规则，需由测试与实际页面共同证明。

## 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 不匹配的截图再次成为样式依据 | 改错页面、重复返工 | 只从指定实时 URL 及同一项目历史取证；证据不充分的局部先对照确认 |
| 同一风险在多个工作区出现 | 重复信息、数量或状态不一致 | 明确 P20/P21/P22/P93 各自职责，以现有任务 ID 与状态为唯一依据 |
| 单文件 CSS 层叠复杂 | 样式互相覆盖、回归难定位 | 令牌和页面作用域先行；每个任务只改相关块并运行针对测试 |
| 替换分段控件影响交互 | 点击、键盘或焦点行为回归 | 原生实现单独成任务；在移除运行时前做事件/键盘/选中状态测试 |
| 所有滚动条隐藏后用户找不到更多内容 | 内容不可发现 | 保留触摸/滚轮/键盘滚动；有横向隐藏内容时用边缘提示，纵向长页用明确分区与留白 |
| 基线已有测试失败 | 视觉改动掩盖原有问题 | T17.1/T17.2 先分类失败，只将有效业务约束留下，不用 SHA 锁住整份源码 |
