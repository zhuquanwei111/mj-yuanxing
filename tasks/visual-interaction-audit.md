## 范围与证据边界

本轮只处理视觉、信息组织、导航、操作路径和反馈，并整理原型评审用的外围目录/说明栏。审查对象是 `明镜/1_产品原型/明镜产品原型.html`，辅以用户截图、HTTP预览及用户指定的参考网站；未阅读产品、业务或架构文档。下文问题清单保留实施前审查证据；用户授权后T1–T8已实施，当前状态以覆盖清单与实施记录为准。

HTML 注册了 46 个页面、12 个角色；另有 AI、P41D学员详情和各角色MY个人页。检查了页面注册、实际渲染分支、通用样式、各角色页面模板，以及导航、表单、弹层和滚动处理。全文件盘点有45处页头说明调用、44处AI分工说明调用、34处弹窗调用；这是源码调用数，不是实际可见元素数或已验收数量。没有把文件中闲置的桌面导航当作当前显示的界面。逐页与逐弹窗落实范围见[全原型覆盖清单](page-coverage.md)。

首次审查时，应用内浏览器安全策略禁止打开 `file://` 页面，因此先完成源码审查。2026-10-09用户提供HTTP预览地址后，已实际完成P30工作台/详情/漏斗和P13/P15的局部点击、截图及360/390/430手机视口检查，结果见[浏览器实测记录](browser-validation.md)。下表保留初审证据标注，实测记录说明哪些问题已得到实际显示支持；其他页面及完整路径仍待验证。未统计实际点击耗时。

P0：阻碍定位、阅读或操作，先处理。P1：持续增加理解和操作成本，主线整理时处理。P2：主线稳定后统一收尾。这是本轮设计优先级，不是生产事故级别。

## 核心判断

混乱主要来自五件事：

1. **页面承担了太多任务。** 经营首页混放月任务、指标、异常、周报、行业对标；主播详情混放资料、生命周期、多个动作和五组历史；培训页混放学员、评估、课目管理和全量历史。
2. **业务内容与原型讲解混排，文字层级不清。** 页头重复角色/目标/价值说明；模板中的`ailine()`反复解释AI与人的分工。用户最新决定：这些说明（包括P30“回访第一……”和“主播留存的第一道防线”）均不显示在手机产品画布，统一放到外围评审侧栏；手机只保留用户完成任务所需的状态、风险、结果与操作。
3. **信息的优先级没有变成视觉层级。** 大量白卡、细灰文字、标签和同级按钮使重要异常、普通数据、历史记录都争夺注意力。
4. **导航缺少连续上下文。** 来源、主播、页签、筛选和滚动位置没有作为完整路径保留；不少入口只到模块首页。
5. **窄屏布局仍沿用宽行结构。** 固定列宽、七列周历、横滑页签、多个并排按钮与手机可用宽度冲突。

解决顺序应是：修复手机容器与弹层边界 → 确定全局字级及文案分类 → 明确页面主任务与默认展示 → 整理上下文和操作 → 全原型逐项验收。只换颜色、加留白会让页面变长，不能解决结构问题。

逐页记录“保留并改善／调整层级或按需展开／移至侧栏”的结果。除通用页头与AI组件外，还需检查内联小字、消息时间、日历条目、状态标签、表单提示、弹窗帮助和空状态。

参考[用户指定网站](https://prototype.brightmirror.net/live/index.html)的外围结构：左侧角色/页面目录，中间手机预览，右侧随当前页同步的适用角色、设计说明、主路径和演示限制。手机产品导航只承载业务操作；手机访问时收起外围区域，产品按可用宽高展示。外围评审工具属于本轮范围，桌面产品布局仍暂缓。

### 弹层的手机边界

P30“记沟通”实测浏览器视口539×800，手机壳392px、内屏372px，弹窗460px；横向越界已复现，最大高度为`none`。截图见[弹窗越界证据](browser-evidence/p30-modal-outside-phone.jpg)。

公共弹层定位必须以手机内容视口为参照；遮罩覆盖手机内容并阻止背景误操作，外围目录/说明不被遮罩。居中短弹窗建议左右至少留16px边距；底部面板留安全区；长编辑改独立页面。内容超长时滚动内容区，关闭入口与主操作可达。轻提示、菜单等浮层遵循同一边界，不能只缩小一个弹窗宽度。

34处弹窗调用逐项检查：宽浏览器中的手机预览、360/390/430px手机访问、短屏、长内容、输入聚焦、关闭/取消、焦点与滚动恢复。没有实际软键盘证据时明确保留待验收，不把桌面缩窄视口当作已验证软键盘。

### 方向

使用者是在工作间隙快速处理直播公会任务的人。页面应像一本清楚的值班记录：打开先看到今天的重点，再看当前对象，最后执行下一步。

本产品的组织概念是：班次、主播、场次、预警、交接、回执、开播时间。视觉表达用纸白、记录墨色、设备浅灰、状态绿、提醒琥珀、风险红，不增加无意义装饰。

保留当前黑白基调，暂不进行品牌换色。产品辨识点放在**“主播/场次 → 当前状态 → 下一步行动 → 回执”**这一条连续结构。避免把所有内容做成等大的卡片、把所有AI结果做成大段聊天、把每一个生命周期阶段做成模块跳转按钮。

### 基准值（拟议值，实施时需渲染复核）

| 项目 | 建议 |
|---|---|
| 基础色 | 背景`#F7F8FA`、内容`#FFFFFF`、主文字/主动作`#111827`、辅助文字`#4B5563`、分隔`#E5E7EB`；红/黄/绿只表达风险与状态。 |

| 间距 | 4px基础单位；页边16px；组内8–12px；独立区块24px；卡片内16px。强关联紧凑、独立任务留空，不统一拉大所有间距。 |
| 层级 | 主工作区优先；普通列表用分组行；必要业务引导/价值可读，长依据按需展开，制作说明放外围。卡片不用多层嵌套。 |
